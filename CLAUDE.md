# Tusk — Agent Onboarding

Fast, native, lightweight **Postgres-first database client**. Goal: replace the clunk of pgAdmin and the resource weight of JetBrains DataGrip. Tauri (system WebView, not Electron) + Rust + SolidJS. Launches sub-second, low RAM, ~5 MB installer.

This file is the source of truth for working in this repo. Keep it, `CHANGELOG.md`, and the code in sync.

## Stack

- **Shell:** Tauri v2 (system WebView2 / WKWebView — no bundled browser).
- **Frontend:** SolidJS + TypeScript + Vite + CodeMirror 6.
- **Backend:** Rust + `tokio-postgres` (text/simple protocol), `native-tls`, `keyring`.

## Build / run / verify

```sh
npm install                 # once
npm run tauri dev           # run the app (needs Rust + Node 20)

# Validate after edits (ALWAYS do this before claiming done):
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo build --locked --manifest-path src-tauri/Cargo.toml
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D clippy::correctness -D clippy::suspicious
cargo test --locked --manifest-path src-tauri/Cargo.toml
npm run check:versions
npm run build
npm run typecheck
npx vitest run

# Cross-engine driver conformance (after touching driver.rs / a driver):
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib driver_conformance  # embedded (DuckDB+SQLite)
scripts/conformance.sh                                # + Postgres & MySQL via throwaway Docker containers
```

- **After Rust changes → tell the user to restart `npm run tauri dev`.** Frontend-only changes hot-reload.
- Validation CI (`.github/workflows/validate.yml`) runs on `master`, pull requests, manual dispatch, and a weekly schedule: frontend build/type/tests, Rust fmt/build/clippy/tests, four-engine conformance, dependency advisory/license/source checks, and release-cache warming. Actions and Docker images are pinned; validation permissions are read-only. `npm audit --audit-level=high`, `npm run check:licenses`, and `cargo deny --manifest-path src-tauri/Cargo.toml check advisories licenses sources` are CI dependency gates.
- Installers are built only by `.github/workflows/release.yml` from a `v*` tag (or manual dispatch naming an existing tag). The verify job requires the tag commit on the default branch and exact version parity across `package.json`, `Cargo.toml`, and `tauri.conf.json`; build jobs use the protected `release` environment, fail without `TAURI_SIGNING_PRIVATE_KEY`, and alone receive `contents: write`. macOS arm64/x64 and Windows builds draft the release. Don't cross-compile locally.
- **Built-in updater:** `tauri-plugin-updater` polls `releases/latest/download/latest.json` (published releases only — a draft is invisible to it). CI signs updater artifacts with the `TAURI_SIGNING_PRIVATE_KEY` repo secret (minisign key, empty password; pubkey lives in `tauri.conf.json` `plugins.updater`; keypair at `~/.tauri/tusk.key` on the dev machine — NEVER commit it). Frontend = `src/UpdateBadge.tsx` (bottom-right pill, both screens; silent on check failure). `createUpdaterArtifacts: true` in the bundle config; capabilities add `updater:default` + `process:allow-restart`.
- Production `tauri.conf.json` has an explicit CSP (`script-src 'self'`, no objects/forms/frames, IPC/asset-only connect/img exceptions); `devCsp` remains disabled for Vite/Tauri dev. `capabilities/default.json` grants opener access only to shipped provider key pages and the exact crash-report mailto shape. Keep external destinations allowlisted rather than restoring `opener:default`.

## Conventions

- Update `CHANGELOG.md` (`[Unreleased]`) on every change.
- Run the applicable validation commands above after edits; Rust/driver changes require the Rust and conformance gates, frontend changes require build/type/tests, and version changes require `npm run check:versions`.
- Surfacing errors: `db.rs`'s `From<tokio_postgres::Error>` unwraps the real Postgres message (don't regress to bare "db error").
- Caveman chat style seen in history is a *session* preference (the `/caveman` skill), **not** a code/docs convention — write code, commits, and docs normally.

## Architecture

### Backend — `src-tauri/src/`
- **`lib.rs`** — Tauri command layer and connection registry (`HashMap<id, Arc<Conn>>`; each `Conn` has a closed flag + `AsyncMutex<ConnState>`). `run_query` uses checked engine-aware `script::parse_for_engine`, preflights the complete manual-transaction lifecycle, enforces one owner tab, closes only the old result stream, applies per-tab search path for work statements, and streams only a single cursorable statement. Ordinary idle multi-statements with no transaction control use one app-owned atomic script wrapper and return a summary; explicit-control and already-owned scripts run statement-by-statement on the manual session. It never replays a command after the server may have seen it. `transaction_status` exposes authoritative state; disconnect best-effort rolls back an owned session. `cancel_operation` targets the armed query/fetch/export/import through generation-scoped cancel entries outside the connection mutex; PostgreSQL cancel waits for owner unwind before the next arm. Result/IPC/SQL/file/history payloads are bounded. `validate_sql` remains PREPARE-only and never executes. Export accepts one read-only result query or validated inline rows; import keeps CREATE+COPY transactional. History/text writes and migration use durable atomic replacement. Crash, AI, skills, Slack, relationship, permission, and file commands are registered here; sidebar DDL still reuses `run_query`.
- **`driver.rs`** — `Backend::{Pg,Duck,Sqlite,MySql}` owns execution, paging, reconnect, cancellation handles, read-only enforcement, transaction capabilities/state, database naming, boolean typing, and introspection. Single reads stream with a PostgreSQL cursor or bounded LIMIT/OFFSET pages; ordinary scripts run through one transaction wrapper (MySQL DDL still auto-commits). Manual transactions keep the engine session open across calls; MySQL checks out and probes one pinned connection for explicit, configured-next-transaction, and autocommit-off modes. All drivers incrementally enforce text-result budgets. Binary values normalize to lowercase `\x...` hex; invalid text encoding errors. PostgreSQL cancel is out-of-band; DuckDB uses `InterruptHandle` except on Windows, where interrupt is disabled because it poisons the bundled connection; SQLite/MySQL expose no UI-query cancel handle. DuckDB remains pinned to `~1.4`, parse-gates user/composed SQL, quarantines poison, installs/loads ICU best-effort, and releases idle file locks only when no manual transaction owns them. SQLite uses `sqlite_master`/PRAGMA; MySQL applies session read-only setup on every pooled connection and keeps the duplicate-column pager fallback.
- **`db.rs`** — `ConnectionConfig`, `AppError` (rich error surfacing), `open()` (TLS/sslmode/read-only), `make_tls`/`ssl_mode_of`, and bounded text-protocol collection. `collect_rows_limited` preserves zero-row column headers, rejects multiple result sets, ragged rows, invalid UTF-8, and oversized pages incrementally (`USER_TEXT_LIMITS`: 50k rows / 10k cols / 2m cells / 1 MiB cell / 64 MiB total; catalog/DDL variants differ). Values crossing IPC remain text-or-NULL; PostgreSQL `bytea`, DuckDB/SQLite BLOB, and MySQL binary values use reversible lowercase `\x...` hex. `pg_string_literal` makes backslash handling independent of session settings and rejects NUL. `ident`/`create_table_text`/`copy_rows` support import; `CURSOR_NAME` names the one UI cursor.
- **`profiles.rs`** — saved connections. Metadata → bounded, atomically replaced `<app-config>/connections.json`; password → OS keychain (`keyring`), never plaintext or frontend-visible. Updating driver/host/port/user/database/path while retaining password is forbidden: user must re-enter it, and metadata/keychain changes use rollback plus a credential-free handoff so a crash cannot bind a new secret to the old destination. Delete/restore keychain failures surface.
- **`script.rs`** — SQL parser/runner. `parse_for_engine()` is the checked execution lexer (`split()` remains lenient for editor classification): comments, engine-specific strings/identifiers/comments, dollar bodies, and top-level `COPY … FROM stdin` + `\.` data. `transaction_action` recognizes raw `BEGIN`/`START TRANSACTION`, `COMMIT`/`END`, `ROLLBACK`/`ABORT`, savepoint/rollback-to/release, unscoped `SET TRANSACTION`, and MySQL session autocommit forms. `preflight_transactions` validates the whole lifecycle before execution: no nested/prepared/chained units, failed-state work, unsupported engine features, hidden MySQL executable controls, or implicit-commit statements inside an owned MySQL transaction. Ordinary idle scripts remain app-owned and atomic; explicit-control scripts are not nested in that wrapper. PostgreSQL inline COPY participates in whichever transaction owns the script. `effective_start()` skips leading comments.
- **`export.rs`** — options-driven CSV/TSV/JSON/SQL/Markdown/xlsx export shared by full-query, loaded-row, clipboard-parity, and Slack paths. Every sink validates options, columns, projections, row shape, duplicate JSON names, 1 MiB values, and metadata/output budgets. File paths use sibling temp files, sync, and atomic replacement; failure/cancel leaves the previous destination untouched, while zero rows still produce a valid configured artifact. SQL output is source-dialect aware (PostgreSQL/DuckDB/SQLite/MySQL identifiers and safe literals) and batches multi-row INSERTs by tuple count plus bytes. PostgreSQL uses a snapshot cursor; other drivers page through the same feeder. xlsx uses constant-memory worksheet tempfiles and rolls at 1,048,576 rows. Boolean export parity remains `export.rs` ↔ `src/formats.ts` ↔ `src/grid/bool.ts`.
- **`tree.rs`** — introspection. `build_shallow()` = fast connect-time tree (`DbTree { database, databases, schemas[] }`, each schema's tables/views/sequences/functions as **name+kind stubs** + table comment; includes empty schemas). `RelStub` also carries `rows: Option<i64>` (planner `reltuples::bigint`; `-1`/never-analyzed → `None`) + `size: Option<String>` (`pg_size_pretty(pg_total_relation_size)` for tables/matviews only, via a relkind-guarded CASE) — non-PG drivers construct stubs with `None`. `table_detail(schema, name)` = lazy per-relation columns (with `is_pk`/`is_fk`/nullable/default/**comment**), indexes, constraints, **triggers** (`pg_trigger`/`pg_get_triggerdef`, `NOT tgisinternal` so FK-internal triggers stay hidden; non-PG drivers return `vec![]`) — resolves the relation's OID via a **parameterized** query, then drives detail queries by that trusted integer.
- **`ai.rs`** — AI proxy for `Wire::{Anthropic,Gemini,Openai,Responses}`. Provider id is the OS-keychain account; keys are stored as origin-bound records, legacy raw keys work only at the shipped provider origin, custom keyed origins require explicit approval and HTTPS, and redirects are disabled. Requests validate provider/wire/model/base/messages/roles and enforce 4 MiB input/output, 1 MiB SSE-line, and bounded model/error bodies. SSE parsing handles deltas, provider errors, finish/truncation, final unterminated frames, retry-before-visible-output, and cancellation. Tiny deltas batch at 1 KiB or 30 ms before Tauri IPC. `ai_list_models` uses the same origin-bound credential and keyed Test uses a real completion endpoint, never a public model-list 200.
- **`slack/`** — desktop-hosted Socket Mode bot. Socket envelopes are acked before work, deduped, bounded, and processed sequentially. A question snapshots schema/perms/FKs/skills and optional default-off samples, then AI may propose exactly one wrappable read. Proposal and result ids are 128-bit OS-random capabilities; interactions also bind current allowlists, requester, workspace, channel, thread, exact source message, TTL, connection id, and database. SQL is revalidated at proposal and execution with mutation/lock/output scans, executable-comment rejection, and a conservative deterministic-function allowlist. Approval refuses a changed connection/database and runs on a fresh engine-enforced read-only backend, never the UI cursor; file-backed DuckDB requires no active UI stream and in-memory embedded databases are refused. Results page under live budgets, retain at most 8/64 MiB for 15 minutes, and requester-only export buttons reformat without rerunning. PostgreSQL timeout sends server cancel; MySQL may finish after Tusk stops waiting; embedded calls are synchronous. Config/tokens save transactionally, replacement tokens restart a running bot, and non-token settings apply next question.
- **`skills.rs`** — user-authored AI instruction bundles (`workspace` or server-reported database-name scope). On-disk/export format is one Markdown file with five scalar frontmatter keys under `<app-config>/skills/`; plain Markdown is a valid import. Limits: 256 regular files, 256 KiB each, id 128 bytes, name 200 bytes, description 2 KiB, database 512 bytes. The skills directory and files reject symlinks/reparse points; create is no-clobber, replace is atomic/synced, and Unix files are mode 0600. `safe_id` blocks traversal; scalar newlines cannot forge keys; corrupt `enabled` stays on, unknown scope degrades to workspace, and one unreadable file does not take down `load_all`.
- **`perms.rs`** — Postgres permission model. `collect(client)` → `Permissions` (the role's **effective** privileges via `has_*_privilege`, accounting for membership/`PUBLIC`/ownership): role attrs (superuser/createdb/createrole), per-schema CREATE/USAGE+owner, per-relation SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER+owner (one `pg_class` scan), CREATE-on-current-db. `Backend::permissions()` → PG delegates here, others return `Permissions::unrestricted()` (`enforced:false`). Exposed by the `permissions` command; frontend gates sidebar DDL on it. **Bare `has_*_privilege()` bools come back `"t"`/`"f"` over the text protocol — never `::text`-cast them.**
- **`ddl.rs`** — `object_ddl(kind, schema, name)` reconstructs runnable `CREATE` DDL from `pg_catalog` (pg_dump-style): tables (identity/generated/serial defaults; PK/unique/check inline; **FKs as trailing ALTERs**; plain indexes only — constraint-backed skipped; table+column comments), views/matviews (`pg_get_viewdef`), functions (`pg_get_functiondef`, overloads; aggregates/window flagged via `prokind`), sequences (`pg_sequences`). User input bound as params, then by OID. Out of scope: partitions, inheritance, RLS, triggers, storage params, tablespaces, collations.
- **`main.rs`** — `tusk_lib::run()`.

### Frontend — `src/`
- **`App.tsx`** — workbench shell: four-driver connect/profile flow, capability-gated toolbar/sidebar actions, per-tab SQL/results/search-path state, query execution, cancellation, import/export, DDL dialogs, plans/ERD, AI/history panels, and revision-safe persistence. `executeQuery` is the one run path: it reopens hidden results, binds all async writes to a connection/tab/result generation, records base history plus grid Apply, and tracks the single cursor owner. A single cursorable statement may stream; scripts return summaries. Manual transactions render one owner bar with id/mode/state/time and Commit/Rollback/configure/lost actions; other tabs and session-backed metadata freeze. Owner-tab/window/disconnect close paths require resolution, pending grid edits must Apply/discard first, and interrupted/lost sessions warn without restoration. File saves serialize by destination and preserve dirty state for newer revisions. Recovery snapshots capture the active CodeMirror document and block disconnect when dirty data cannot be verified in localStorage. Export dialogs use frozen producing-tab/connection snapshots. Metadata, dialog, clipboard, paste, Slack-history, and timer completions reject stale origins. Permission/capability gating remains defense-in-depth over backend enforcement.
- **`transaction.ts`** — frontend authoritative-state core: validates monotonic status revisions per connection generation, classifies raw control scripts for history/provenance, permits only recovery-first runs in failed state, scopes history by transaction identity, marks transaction/pre-transaction results and pending edits stale at commit/rollback/rollback-to/loss boundaries, computes owner-bar action availability, and bounds the advisory interrupted-transaction localStorage marker.
- **`ResultGrid.tsx`** — two-axis virtualized editable grid with synchronized header/gutter panes and stable `RowRef` identities. Inserts stay pinned above loaded rows; pending edits overlay immutable snapshots. Menus and paste bind active tab + result generation and become inert after replacement. Copy/clipboard work caps at 1,000,000 cells and 8,388,608 source characters; edit/delete actions cap at 100,000 rows. Paste uses strict TSV/CSV parsing, validates row order/identity and unique header mapping, and merges through pure helpers. Display order may map through completed-result local sort without changing canonical row identity. Per-tab widths/order/hidden/sort/filter live in `GridView`; scroll stays outside reactive persisted state.
- **`Tree.tsx`** — recursive explorer. Per-row right-click → `onContext(e, NodeDescriptor)`; click/right-click select (`onSelect` + `selectedKey`/`nodeKey`, drives the context-aware **＋** menu); lazy detail via `onExpandTable`; client-side `filter`. Relation expand keys are kind-prefixed (`tbl:`/`view:`) to avoid table/view collisions.
- **`ContextMenu.tsx`** / **`Dialog.tsx`** / **`WorkbenchDialogs.tsx`** — generic right-click menu; modal shell + `SqlPreview` + `DialogFooter` (live SQL + Cancel/Edit-as-SQL/primary); dispatcher rendering the form for the active `DialogState` (union with per-form payloads + closures).
- **`forms/*`** — one component per action (CreateTable, Column add/edit, **ModifyTable** = DataGrip-style diff editor, Index, Constraint, Schema, Database, Rename, Duplicate, Comment, generic Confirm for drop/truncate). Each owns local state, derives a live `createMemo` SQL preview, and calls back `onRun`/`onEditAsSql`. `ModifyTableForm` diffs an edited column list (+ index/constraint drops + table rename/comment) into the minimal `ALTER` script.
- **`SqlField.tsx`** — single-line CodeMirror with Postgres highlighting + autocomplete (types / functions / passed columns); used for type/default/expression fields in the create & modify dialogs.
- **`sql/ddl.ts`** — pure SQL builders (the heart of "build SQL in TS"), **dialect-aware via `isDuck()` = `sqlDialect()==="duckdb"`**: DuckDB emits one `ALTER` action per statement (not comma-joined), splits `ADD COLUMN` constraints into follow-up `ALTER`s with NO backfill (DuckDB rejects `SET NOT NULL` with an outstanding UPDATE in the same transaction, and the run path is transactional — so NOT NULL adds work on empty tables only), uses CTAS for duplicate, and drops PG-only clauses (index method / `AUTHORIZATION` / `TRUNCATE` options). Constraint-ALTERs / rename-index|seq|constraint / CREATE DATABASE are gated in `App.tsx` via `noDuck`, not emitted here. Covered by `sql/ddl.test.ts` (builder output) + `driver_conformance.rs` `duckdb_ddl_builder_forms_apply`/`duckdb_ddl_split_runs_transactionally` (DuckDB executes every form). **`sql/ident.ts`** — `ident`/`qualify`/`lit` quoting (mirrors Rust `db::ident`) + `sqlDialect()` (the real driver kind, set off `caps().kind` — NOT the editor dialect, which maps DuckDB→postgres).
- **`SqlEditor.tsx`** — CodeMirror 6, now a thin **composer** over `src/editor/*` extension factories (using `Compartment`s for live dialect/theme/auto-fold reconfigure — no rebuild, no history reset). Dialect highlighting, **override autocomplete** (context-aware), live keyword auto-capitalization, layered **lint**, folding, search, multi-cursor, statement gutter, **Tab/Enter accept** (both via `acceptCompletion`, a no-op when no popup is open so Enter still newlines). `EditorApi`: `getRunText`/`getCurrentStatement`/`getDoc`/`insertAtCursor`/`format`/`openSearch`/`focus`/… The value effect replaces the whole doc but is **guarded** (`applyingExternal` + `addToHistory.of(false)`), so restores/file-opens don't echo through `onChange` or pollute undo; scaffolding still uses `insertAtCursor`.
- **`editor/`** — the editor's extension modules. `lexer.ts` (**keystone**: TS port of `script.rs` `split`/`dollar_tag_end`, `maskNonCode`, `lexState` shared cache), `autofold.ts` (display-only large-literal folding), `foldBasics.ts` (manual fold gutter + SQL paren fold service), `heuristicLint.ts` + `schemaLint.ts` + `serverLint.ts` + `lint.ts` (two `linter()`s: sync client @300ms, async server @600ms; the heuristic linter flags an unknown **leading** keyword per statement — `STATEMENT_STARTERS` union in `sql/dialects.ts` + did-you-mean via `distance.ts`; cursor-adjacent prefixes of real keywords are skipped while typing. **schemaLint is the production layer**: unknown qualified cols, unknown tables, unknown **bare** columns (gated: DML head, all tables resolved, no CTEs/derived tables), unknown **functions/procs** against the live catalog (`list_functions` command → App `funcs` signal → `clientLint(getSchema, getFuncs)`; EMPTY catalog = that lint off — MySQL can't enumerate builtins), and one-edit-away clause-keyword typos. NOT-a-column vocabulary = `ALL_SQL_WORDS`/`ALL_SQL_FUNCTIONS` unions in `sql/dialects.ts` — bias generous, a missing word is a false positive. `EXTRACT(YEAR FROM x)`-style FROMs are blanked before table scanning (`maskFnKeywordArgs`). Core is pure (`schemaDiagnostics`) + vitest-covered — keep new checks testable there. Quick-fixes apply via keyboard: Tab (after completion-accept, before indent) / Alt+Enter / Mod-. → `applyLintFix` in lint.ts; `closest()` in distance.ts treats a candidate starting with the typed word as one edit — "master"→"master_id"), `theme.ts`/`lightTheme.ts` (oneDark or hand-rolled light theme + `fontStack()`; `themeFor` receives a *resolved* theme, never "system"), `format.ts` (`sql-formatter`, dollar-quote carve-out), `search.ts`, `multiselect.ts`, `statements.ts` (run gutter + active-statement + cursor readout; a `runningField`/`setRunningEffect` swaps the running statement's `▶` for a spinner — the field stores the run-start ANCHOR POSITION (selection head at dispatch, mapped through edits), not the live cursor, so clicking other statements doesn't drag the spinner — App passes `running={running() && runningTabId()===activeTabId()}` to `SqlEditor`, which re-applies it via effect after each tab switch since `setState` resets the field), `keywordCase.ts`, `theme.ts`, `distance.ts` (Damerau-Levenshtein), `types.ts` (`EditorPrefs`/`ValidateFn`/…). **`src/store.ts`** (NOT under `editor/`) — localStorage `prefsStore` + `keymapStore` (shortcut overrides) + `tabsStore` (per-connection tab set: buffers/paths, not results). **`tabs.ts`** — `Tab`/`ResultSnapshot`/`makeTab`. **`export.ts`** — `ExportOptions` (+ `formatWithOptions` lives in `formats.ts`, parity with Rust); **`forms/ExportDialog.tsx`** — the configurator.
- **Editor work limits (`editor/limits.ts`).** Above 1,000,000 document characters, run/open/save remain available, while live client/server lint, statement decorations, keyword casing, and fold discovery disable; Format returns the source unchanged. Below that threshold, diagnostics, statements, fold candidates, active-statement lines, schema dimensions, and suggestion pools/runs remain capped. Keep explicit full-buffer commands separate from live-analysis limits.
- **`ai/`** — provider registry + AI panel. `providers.ts` is the source of provider ids (keychain accounts), wire/base routing, models, and tier metadata; OpenCode Go and Zen remain distinct and may select wire per model. `store.ts` persists bounded per-provider model/base settings, exact approved origins, and default-off `shareSamples`; persistence failure forces samples off in memory and removes stale permissive state where possible. `AiPane` requires custom-origin approval before key save/test and passes the approved resolved base to origin-bound keychain commands. `AiPanel` rechecks sample consent and the exact provider/model/wire/base after asynchronous FK/sample loading, then streams over request-id-scoped channels; backend deltas are UI-coalesced at 4 KiB or 32 ms. Errors/cancel/truncation stay message metadata, generated SQL never auto-runs, and sample data remains cached/budgeted only after explicit opt-in.
- **`help/`** — the in-app manual ("Tusk manual", topbar `?` / `openHelp` action, default `F1`; works on BOTH screens — its dialog + SettingsDialog render in the shared tail of App.tsx, outside the `conn()` Show, and `onWindowKey` whitelists `openHelp`/`openSettings` while disconnected). **`content.ts`** is ~120 KB of GENERATED static topic data (16 topics; drafted per-topic against the source + adversarially fact-checked + concision-edited by the `draft-help-content`/`tighten-help-content` workflows) — regenerate rather than hand-tweak facts; groups live separately in **`nav.ts`** because content.ts is regenerated wholesale. **`types.ts`** (Block union: p/h/code/list/table/tip/keys/demo), **`inline.tsx`** (inline md: **bold**/`code`/*italic* + `[[kbd:Chord]]` chips via `displayKey` + `[[topic:id|label]]` links that degrade to plain text for unknown ids), **`search.ts`** (PURE + vitest-covered: `splitSections` — preamble + h-delimited sections with first-paragraph previews — and `buildIndex`/`search` — multi-term AND, title>section>body ranking, snippet + highlight ranges), **`demos.tsx`** (10 CSS-loop vignettes, keyframes in App.css `.kbd-*`, `prefers-reduced-motion` honored), **`HelpDialog.tsx`** (default export — App loads it via `lazy()` so the content chunk stays out of the main bundle; grouped nav + search-first pane + accordion sections collapsed by default; `keys` blocks render the LIVE binding from the actions registry, so rebinds show instantly; keys rows with unknown action ids are silently filtered — content survives action renames). Adding an action others should discover = also add a keys row in content.ts (shortcuts + workspace topics).
- **Collapsible panels + safe resize (App.tsx):** `toggleSidebar` (Mod-b) / `toggleResults` (Mod-j) actions + topbar panel buttons; collapsed state persists in `layoutStore` (`tusk.layout`). **`executeQuery` reopens a collapsed results panel before running** (single shared runner — every run path funnels through it) so output can never land hidden. Every docked panel clamps against the LIVE window (`maxSidebarW`/`maxSideDockW`/`maxEditorH`, re-applied on load + drag + window `resize`) — a size saved on a big monitor can never cover the editor on a smaller one; don't add a panel without wiring it into `clampPanels`.
- **`settings/SlackPane.tsx`** — Settings → Slack config with masked keychain token inputs, enable/test controls, allowlists, row/timeout/token caps, charts, destructive reply policy, and default-off **Share sample rows with AI**. It mirrors the currently approved AI provider/wire/model/base; unapproved overrides are preserved so the backend fails closed rather than silently using a default origin. Saves are read-back verified. Replacing tokens validates and restarts a running bot; restart failure stops and disables it. Non-token settings apply on the next question.
- **`sql/dialects.ts`** — per-dialect keyword/function/type lists + CodeMirror dialect. Postgres complete; **MySQL/SQLite/MSSQL staged** for future drivers.
- **`sql/aliases.ts`** — shared schema-index + alias resolution (`aliasMap`/`tableByRef`/`currentStatement`/`makeIndexer`/`Col`/`Table`), used by **both** `completion.ts` and `editor/schemaLint.ts` so they never diverge.
- **`sql/completion.ts`** — the context-aware completion source: clause detection (tables after FROM/JOIN, columns after SELECT/WHERE/…), alias resolution (`u.` → that table's columns), schema qualification, ranked in-scope cols > tables > functions > keywords. `$` deliberately excluded from completion tokens. (Index/alias helpers now live in `sql/aliases.ts`.) 4th arg `getFkEdges` feeds **FK-aware JOIN hints**: right after `ON`, `sql/joinHints.ts` `joinConditions` proposes full conditions (`o.user_id = u.id`, multi-col AND-ed, boost 95) from `sql/fk.ts` `FkEdge`s (camelCase mirror of `relgraph.rs`); App fetches edges via `schema_relationships` for active schema + public, lazily per schema (`fkEdges` signal, `fkFetched` set cleared on introspection reload).
- **`sql/params.ts`** — pure param detection + substitution for the pre-run prompt (`detectParams`/`substituteParams` over the lexer's `maskNonCode`): `$1` positional + DB-API `%s` positional-by-occurrence + `:name` named (prev-char guards kill `::casts`/slices/adjacency), spans replaced right-to-left, values as NULL / raw / `lit()`. `%s` formatting is pinned by `editor/format.ts`'s custom param token; `a%s` remains compact modulo, `%%s` remains escaped. Every run/Explain path funnels through App's `runParameterized` → `ParamDialog` (`forms/ParamDialog.tsx`); values are remembered per tab (`Tab.paramValues`), while persistent history stores the unexpanded template. For Postgres `ANY(%s)`, quoted `{1,2}` or raw `ARRAY[1,2]` works; Python list syntax is not adapted. Known false-positive: `arr[i:j]` slices (raw mode is the escape hatch).
- **`grid/editable.ts`** — in-grid editability cores, pure + vitest-covered. `editTarget` accepts one plain-table SELECT with only `*`/qualified-star/plain-column items and requires every nested source reference to resolve to the same physical table; joins, comma joins, expressions/aliases, derived/table-function/CTE/unknown sources, and qualifier mismatches reject. `editPlan` requires table metadata, non-colliding names, a PK fully present in unique result columns, and returns `{pkIdx,isTableCol}`. **`grid/editSql.ts`** builds UPDATEs → DELETEs → INSERTs; WHERE uses original snapshot PK values (composite grouped AND, NULL → IS NULL), delete wins, and untouched insert cells omit their column (`DEFAULT VALUES` / MySQL `() VALUES ()`).
- **`formats.ts`** — bounded CSV/JSON import parsing plus loaded-result/clipboard export formatting. It rejects malformed quote tails, duplicate/empty headers, wider-than-header rows, duplicate JSON keys, deep JSON, ragged datasets, invalid projections, and oversized output. `formatWithOptions` remains parity-bound to Rust `export.rs`, including source-dialect SQL literals.
- **Adversarial input boundaries.** Resource ceilings exist at every trust boundary: SQL/text/history/tabular IPC, database pages/catalog/DDL, imports/clipboard/grid edits, persistence, plan/ERD parsing, export, AI, Slack, skills, and crash reports. Oversized/malformed inputs return errors or bounded defaults; exact limits and unavoidable pre-validation allocation risks live in `docs/adversarial-hardening.md`. Durable user files use sibling temp + sync + atomic replacement where applicable. Skills/crash files additionally reject links/reparse points and use restrictive Unix permissions.
- **Completed-result local sort.** `src/grid/sort.ts` returns a stable visible ordering of canonical loaded-row indices. `App.localRowOrder` activates it only for `done && rowsAreBase && no filters`; `ResultGrid` maps display rows back through `loadedOrder`, so edits/deletes/paste/copy/loaded export retain canonical identity. Incomplete streams and filters still use server wrappers. Values lack portable result type/collation metadata, so local comparison is deterministic text ordering with engine-specific default NULL placement, not native numeric/date/collation semantics; SQL `ORDER BY` remains the exact-server path.
- **Slack execution isolation.** Each proposal pins requester + current allowlists + workspace/channel/thread/message/TTL + exact connection/database. Execution rechecks all bindings, requires the same active connection/database, clones its server-side config, and opens a fresh read-only backend. It cannot join/rollback a UI transaction or use `tusk_cur`; file-backed DuckDB releases only an idle handle and refuses approval while its UI stream is active. In-memory DuckDB/SQLite are refused. Results page in batches under live cell/value/aggregate budgets before byte-capped retention.
- **Connection/persistence and revision safety.** Ad-hoc connection keys are JSON tuples captured before connect awaits. Legacy tab/history migration writes and verifies the collision-proof destination before deleting old storage. Tab recovery captures the live editor document + dirty bit, read-back verifies localStorage, warns on failure, and blocks disconnect/close when dirty recovery is unsafe. File saves serialize per destination and clear dirty only when the written revision is still current. History revisioning merges early appends with an in-flight load and prevents stale disk state from resurrecting a deliberate clear.

## Gotchas (read before debugging)

- **Values are text, but binary is explicit.** IPC cells are string-or-NULL. PostgreSQL `bytea`, DuckDB/SQLite BLOB, and metadata-confirmed MySQL binary columns render as reversible lowercase `\x...` hex. Invalid server-encoding text is an error, never a replacement placeholder, because the original bytes are unavailable. Use `try_get`, never `get`, on tokio-postgres rows; typed catalog readers must degrade/skip on NULL/type mismatch. Every collection path must use the correct incremental `TextLimits`.
- **Crash/skill file boundaries.** Rust panic hook → bounded `<app-config>/last-crash.txt`; frontend `CrashGuard` bounds reports to 96,000 bytes and contains render/window errors. Crash files max at 128 KiB, require regular UTF-8 files, reject symlinks/reparse points, use atomic synced replacement, and are mode 0600 on Unix. Consent remains `tusk.crashConsent`; off clears retained reports and nothing auto-transmits. Skills similarly cap at 256 regular files × 256 KiB with bounded scalar fields and safe ids. Perf guards: editor live analysis stops at 1m chars, grid copy caps at 1m cells/8,388,608 chars, ERD at 600 tables/4,000 edges, plans at 2,000 nodes/depth 256, and Slack chart/event handling remains panic-contained with finite values only.
- **DuckDB parser errors poison the connection — never let user SQL hit it unparsed.** The bundled libduckdb (duckdb-rs #209, seen on Windows) leaves an internal mutex locked after a PARSER error (binder/catalog/runtime errors are fine): every later statement fails with "resource deadlock would occur" and **dropping the poisoned connection aborts the process** ("Rust cannot catch foreign exceptions"). `DuckConn::parse_check` prepares each user statement on a scratch in-memory connection (`gate` field) first — a failure that poisons the scratch (probe `SELECT 1` fails) is the parse-error class → report it + `mem::forget` the scratch; a failure that doesn't is a binder error from the empty scratch DB → pass through so the real catalog errors properly. Gated: `run_single` (user text AND the CAST-wrap — a trailing `--` comment can swallow the wrap's `)`), `run_script` per statement, `bool_columns` (the COMPOSED `DESCRIBE {sql}` — `SHOW TABLES`/`SET`/`EXPLAIN` parse alone but are parser errors under DESCRIBE). `fetch_page` is ungated on purpose (its `stream_sql` already passed the gate). Single-statement prepare never executes (duckdb-rs auto-executes only the LEADING statements of a multi-statement string) — keep the gate one-statement-at-a-time. **Poison classes the gate can't stop** (`interrupt()`, unforeseen paths) are handled by `quarantine_poisoned`/`quarantine_if_poisoned` — probe `SELECT 1` after an error, take+`mem::forget` a poisoned connection (drop aborts; the leaked handle keeps a file-backed DB locked until app restart) and tell the user to reconnect; `release_idle`/`Drop for DuckConn` route through `forget_if_poisoned` as the last belt. **DuckDB Cancel is disabled on Windows** (`CancelHandle::Duck` returns an error there — interrupt() = certain poison; a query that can't be cancelled beats a database file locked until restart). **Deadlock trap:** the quarantine helpers re-lock `conn` — never call them while a `d.lock()` guard temporary is alive (bind the operation result to a `let` first; two arms in driver.rs carry the comment). Pinned by `duck_syntax_error_survivable` + conformance `syntax_error_recovery_battery` + `duck_from_first_and_pivot_stream` (FROM-first/PIVOT are cursorable on DuckDB — buffering them whole was an OOM-abort class).
- **Single statement vs script.** One cursorable read statement may stream, including on an owned manual session. An ordinary idle multi-statement input with no control uses one app-owned transaction and returns only a summary; its trailing read is not split out, so failure still rolls back prior DML (subject to MySQL DDL/nontransactional-table semantics). Raw transaction-control scripts are lifecycle-preflighted and execute on the owner session instead: they may be self-contained (`BEGIN; …; COMMIT`) or span runs. Multi-statement results keep `baseQuery=""`, so grid wrapping/editing stays disabled. Execution uses checked engine-aware `script::parse_for_engine`; editor classification may use lenient `split`.
- **Manual transaction ownership and recovery.** `TransactionStatus {state,revision,id,owner,mode,health}` is authoritative; non-owner queries/fetch/cancel and all `require_idle` metadata/import/query-export/Slack paths fail closed while it owns the session. Supported controls: `BEGIN`/`START`, `COMMIT`/`END`, `ROLLBACK`/`ABORT`; savepoints on PG/SQLite/MySQL; `SET TRANSACTION` on PG (active, before work) and MySQL (before START); MySQL-only `SET autocommit=0/1` on one pinned connection. DuckDB has neither savepoints nor `SET TRANSACTION`; SQLite has no `SET TRANSACTION`. PostgreSQL statement/cancel errors require rollback or rollback-to recovery. A dropped/unexpectedly ended session becomes `Lost`: never reopen/replay it; disconnect/reconnect and verify outcome. Healthy close/disconnect/window-close must resolve Commit/Rollback after Apply/discard of owner pending edits; disconnect cleanup still best-effort rolls back the physical session.
- **Transaction result provenance and grid Apply.** Every result/pending edit records transaction id + revision. Pre-BEGIN rows must rerun before editing; commit, rollback, rollback-to, autocommit-unit boundaries, and loss conservatively stale affected snapshots while leaving them visible. Outside a manual transaction the grid preview **Commit** uses the app-owned atomic script; inside the owner transaction it becomes **Apply**, runs on the outer unit, clears pending changes on success, and does not commit. Transaction-bar Commit/Rollback is separate. History includes scoped control and grid-Apply markers.
- **COPY detection ignores leading comments** (`effective_start`). pg_dump prefixes every COPY with a `--` block; missing this sends COPY to `batch_execute` → `CopyInResponse` → "unexpected message from server".
- **Keychain in dev:** unsigned `tauri dev` builds re-prompt / invalidate saved passwords across rebuilds (macOS ties items to the code signature). Seamless in signed release builds. `keyring` features are per-OS in `Cargo.toml`.
- **TLS:** `native-tls` (SecureTransport on mac, SChannel on Windows; needs OpenSSL on Linux). `sslmode`: `disable` | `prefer` (default) | `require` (encrypt, no cert verify) | `verify-full` (verify).
- **Read-only mode:** engine enforcement where available plus one uniform client guard. Only read forms pass, and the masked scan rejects writable CTEs, row locks, table/file output, mutation words, and `set_config`; `EXPLAIN ANALYZE` is blocked because it executes its inner statement. Inline COPY/import and sidebar mutations are blocked. Slack adds wrappability, executable-comment, and conservative function-policy gates on top.
- **Dropped connections reconnect, never replay.** `ensure_alive` reopens a closed backend before the next explicit command, but `run_query` never retries after a command may have reached the server, even for read syntax: volatile functions/external effects make outcome ambiguous. The error tells the user to verify state. Connect timeout/keepalives still surface dead PostgreSQL links without capping live query duration. A lost streaming cursor returns an explicit incomplete-result error; fetch errors roll back/reset pager state. Run cancellation is armed for the initial query and each fetch.
- **Autocomplete corrupting dollar-quotes** was caused by Enter-accept **combined with `$` being a completion token** (so `$tag$` delimiters were offered and replaced on accept). The fix that matters is keeping **`$` out of completion tokens** — with that in place, Enter-accept is safe and is now enabled (Enter accepts like Tab; `acceptCompletion` no-ops to a newline when no popup is open). Don't re-add `$` to completion tokens.
- **Lazy tree ⇒ autocomplete uses `list_schema`, not the tree.** The shallow `db_tree` no longer carries columns, so autocomplete is fed by `list_schema` (one query). Expanding a node fetches `table_detail` (cached); after DDL, `runDDL`→`loadSchema` refetches the shallow tree + `list_schema` and re-fetches already-open details.
- **Sidebar DDL must stay single-statement where it matters.** `CREATE/DROP DATABASE` can't run in a transaction — keep them one idle statement (ordinary multi-statement input routes to the app-owned wrapper). Builders in `sql/ddl.ts` emit one statement each (comma-separated ALTER actions, not `;`-joined); multi-statement cases (duplicate-with-data, column edit + rename) are intentionally table-only. Explorer DDL is frozen during manual transactions; raw owner SQL remains engine-authoritative, with recognized MySQL implicit-commit forms blocked inside the tracked unit.
- **Copy DDL is reconstructed, not pg_dump.** Driven by OID; constraint-backed indexes are skipped and FKs deferred to trailing ALTERs so replay doesn't error. Partitions/inheritance/RLS/triggers/storage are out of scope (see `ddl.rs`).
- **Quoting parity + dialect.** `sql/ident.ts` `ident` is **dialect-aware** (`setSqlDialect`): MySQL = backticks `` `x` ``, everyone else = double `"x"`; literals are `'…'` for all. Set once per connection by an App effect off `activeDialect()` (the app is single-connection, so a module var avoids threading a dialect arg through scaffolds/grid-filters/DDL builders). For **Postgres** it matches Rust `db::ident` — and `db::ident` is only used on PG-only backend paths (import / DDL recon), so the parity that matters is PG↔PG. **Editor dialect follows the connected driver**, not a manual selector: `activeDialect = conn() ? driverDialect(caps().kind) : prefs().dialect` (DuckDB → `postgres` dialect; the old toolbar dialect `<select>` was removed). Always quote identifiers in generated SQL.
- **Never `::text`-cast a boolean in catalog queries.** `collect_rows` reads the text protocol: a *bare* bool comes back `"t"`/`"f"`, but `bool::text` (e.g. `i.indisunique::text`, `(con.oid IS NOT NULL)::text`) comes back `"true"`/`"false"`. The code compares against `"t"`, so a cast silently makes every check false. Select the bare bool (`i.indisunique`, `(NOT a.attnotnull)`). Char columns (`relkind`, `attidentity`, `contype`) DO need `::text`.
- **`editor/lexer.ts` must mirror `script.rs` lexical boundaries.** Auto-fold, lint, formatter carve-outs, current-statement selection, and safe grid wrapping share it; keep dollar-tag/parameter/comment/string semantics aligned. Execution uses checked Rust `script::parse`, while TS/editor classification and Rust `split` remain lenient, so psql meta-commands and malformed inline COPY are rejected only at the execution boundary. Server-lint statement indices can still diverge around COPY data.
- **Auto-fold is display-only.** It replaces ranges with widget decorations; the document text is never modified, so `getRunText`/`getDoc`/export always return the full expanded query. Folds recompute on doc-change (candidate geometry) and on every selection move (cursor in a range → expanded). Don't reach for `@codemirror/language` fold state for this — that's the separate *manual* fold gutter (`foldBasics.ts`).
- **One cursor, many tabs.** There's a single server-side cursor per connection (`tusk_cur`), so only one tab can stream at a time. `doRun` frees another tab's cursor and marks its snapshot `done` before running; `cursorOwnerTabId` gates `loadMore` so scrolling a non-owning tab never `FETCH`es the wrong cursor. Idle sidebar commands roll the cursor back; during a manual transaction they are frozen, and an owner run closes only the old stream without rolling back the outer unit. Per-tab editor state (undo/cursor/fold) lives in a `Map<tabId,EditorState>` in `SqlEditor.tsx`; **`view.setState()` replaces all state incl. compartments**, so every tab state is built via the shared `buildExtensions` (seeded with the current dialect/theme/fold), and the guarded value-effect skips during a swap (`props.tabId === curTabId`) so it can't clobber the outgoing tab.
- **Grid `<For>` bodies must read via accessors, not `const`.** In `ResultGrid.tsx` the windows iterate index ranges (`range(visCols…)`); inside, use `const oi = () => displayCols()[k]` / `const val = () => rows()[r]?.[oi()]` (functions), NOT `const oi = displayCols()[k]`. A plain const is captured once at item-render; since the `For` key (the index) doesn't change on a sort re-run (rows replaced) or reorder (displayCols changed) with the same window, captured consts go stale and cells show old data / the sort glyph never appears. Read reactively in the JSX. The grid's frozen header/gutter are transform panes (not sticky); a new query bumps `result.epoch` so the grid resets scroll (vs a tab switch, which restores it) — keyed on `${tabId}:${epoch}`. **That key MUST be a `createMemo`, not a plain `() =>` function.** `on()` re-runs its callback whenever a tracked dep *notifies*, not only on value change, and `epoch` reads through App's `activeTab()` memo whose identity changes on every `patchTab`/`patchResult` — so a plain key fired the reset (scrollTop→0 + selection clear) on every row append / resize / reorder / hide, making those feel broken. The memo dedupes by string so the reset runs only on a real tab switch or epoch bump. **Scroll never writes to reactive state**: `onScroll` updates only the local `scrollTop`/`scrollLeft` signals (only the window memos depend on them) + a non-reactive per-tab `scrollMem` Map. Persisting scroll into `gridView`/`setView` per frame rebuilds the tabs array and cascades a full-App recompute every frame — it froze/crashed large tables. Keep scroll out of `view`.
- **Active schema is per-tab, applied per run.** `Tab.searchSchema` (null = default) drives `SET search_path` on the *shared* session — so it must be re-applied (or `RESET`) on every run_query/validate/export, never assumed sticky. Autocomplete labels a table bare when its schema is `public` or the active schema (`makeSqlCompletion`'s 3rd `getActiveSchema` arg). Export scope=all uses the *producing* tab's schema via the `exportSrc` snapshot. Schema-lint still resolves bare names via `byBare` (no active-schema preference yet — minor, deferred). **Generated query scaffolds** (`genSelect`/`genInsert`/`genUpdate`, `runTable`) use `qualifyIn(schema, name, activeSchema)` — drops the schema prefix when it matches the tab's active schema — and open a **new tab** via `openGeneratedTab` (schema set to the relation's) rather than clobbering the active tab. DDL builders keep using `qualify` (always explicit — never depend on search_path for drop/alter/rename).
- **Native widgets need `color-scheme`, not CSS colors.** The `<select>` **popup**, scrollbars, and checkboxes are painted by the WebView, not by our CSS — styling the select box (`background: var(--bg)`) does nothing for the popup. `:root` declares `color-scheme: dark` and `:root[data-mode="light"]` declares `light`; without it the popup renders light while `<option>` inherits the dark theme's near-white `--text` (white on white). Explicit `select option, select optgroup` colors are belt-and-braces for webkit2gtk. Keep `color-scheme` keyed to `data-mode`, not to `data-theme` — polarity, not palette.
- **Lint squiggles: SVG background, not `text-decoration: wavy`.** WKWebView (the macOS Tauri runtime) renders `text-decoration-style: wavy` unreliably. `.cm-lintRange-{error,warning,info}` in `App.css` use a repeating inline-SVG wavy underline (CodeMirror's own mechanism), recolored. Don't set `background: none` on those (it removes the squiggle), and don't rely on `wavy` text-decoration. Lint diagnostics are generated by the client (heuristic+schema) + server linters regardless — this is purely the *painting*.
- **Export parity + scope.** `export_to_file` accepts one safe read query (all rows) or validated inline rows (loaded). `formatWithOptions` must remain byte-parity with Rust for delimiters/null/header/projection/line endings/booleans and source-dialect SQL literals/identifiers. JSON object output requires unique columns. Every file path is sibling-temp + sync + atomic replace; empty results replace stale destinations with valid configured output, failure/cancel preserves the old file. Query export cancellation covers type discovery + paging; loaded-row/clipboard formatting has no armed DB operation and is bounded instead. xlsx is constant-memory and rolls sheets at 1,048,576 rows.
- **`validate_sql` never executes.** It uses checked `script::parse`, then PREPARE/DEALLOCATE in autocommit after cursor rollback. It skips DDL/utility/COPY/transaction starters and runtime parameters; malformed COPY/psql meta input errors before PREPARE. The frontend skips server lint while any query/stream is active and above the 1m-character live-analysis cap. Position mapping still subtracts the PREPARE prefix and restores statement whitespace offsets.
- **Scope by `Backend::database_name()`, never `ConnectionConfig.dbname`.** `dbname` is the field the USER TYPED: blank for DuckDB/SQLite (path-based) and blank on Postgres whenever libpq defaults it. `database_name()` returns what the server reports — the same value `DbTree.database` (and therefore the sidebar and `aiContext().database`) carries: `current_database()` on PG/DuckDB, `database()` on MySQL, literal `main` on SQLite. **AI skills scope on this in both the panel and the Slack bot**; scoping on `dbname` made a database-scoped skill apply in the panel and silently vanish for the bot. `driver_conformance`'s `database_name_battery` pins `database_name() == build_tree().database` on all four engines.
- **Providers are data; wires and origin trust are code.** Provider id is the keychain account and must never be renamed. `providers.ts` resolves model-specific wire/base; `ai.rs` implements the four wire shapes. A keyed custom base requires explicit frontend origin approval and HTTPS, and saving writes the key with that exact origin; legacy raw keys work only at shipped provider origins. Slack must mirror the requested resolved base/wire, including an unapproved override so Rust fails closed rather than silently rerouting context. `/models` success is not credential proof; keyed Test uses a tiny completion.
- **An SSE frame that isn't a delta is not nothing.** Providers report failures *inside* a `200 OK` stream (Anthropic `{"type":"error"}` for overloaded/rate-limit, OpenAI `{"error":{…}}`, Gemini `promptFeedback.blockReason`) and report truncation via a stop reason (`max_tokens`/`length`/`MAX_TOKENS`). The original parser matched only the delta pointer and treated everything else as `Ignore`, so a mid-stream failure ended the loop and emitted **`Done`** — the UI showed a truncated reply as a finished one, and Slack turned a half-written (unclosed ```sql fence) reply into the hardcoded "I can't help with that from Slack — try the Tusk desktop editor," blaming the user's question for a provider outage. When adding a provider, wire up **all three** of `extract_delta`/`extract_error`/`extract_finish` and add its frames to `ai.rs`'s tests; a provider whose errors you don't parse fails silently, which is strictly worse than failing loudly. Two traps: `"error": null` on every frame (vLLM/LiteLLM) is not an error, and a frame can carry a delta *and* a finish reason at once (Gemini's last chunk) — hence `Frame` is a struct, not an enum. Retry only replays when nothing has been painted yet (`soft_fail(msg, emitted && partial_is_fatal)`); the streaming path must never re-stream over visible text.
- **Slack bot invariants.** No query runs without a scoped, requester-only Approve click. Action ids are random capabilities but must also match allowlists/workspace/channel/thread/exact message/TTL and the proposal connection/database. SQL is one wrappable read, mutation/lock/output/executable-comment free, and limited to common deterministic unqualified built-ins; validate at proposal and execution. Run only on a fresh engine-enforced read-only backend, never shared cursor/session. Ack before work and dedupe event ids. PostgreSQL timeout cancels server-side; MySQL may continue after timeout; embedded calls are synchronous. Samples default off. Config reloads per event; token replacement restarts. `slack/context.rs` remains parity-bound to AI context/skills.
- **In-grid editing: pending overlays, strict provenance.** Snapshot rows never mutate; Apply/Commit WHERE uses original PK values and generated scripts remain atomic in the app-owned or existing outer transaction. Edit only a single plain table with unique/non-case-colliding metadata, complete PK, and select items limited to `*`, `t.*`, `col`, or `t.col`; reject CTE/table/values, joins (including comma), expressions/aliases, derived/table-function sources, mismatched qualifiers, and unresolved/multi-table nested refs. Generation-bound menus/paste cannot target replaced results; transaction id/revision must still match; each edit action caps at 100k rows. Paste validates row identity/order and unique header mapping. Defense-in-depth still blocks non-table columns, cols-mode deletes, empty commits, and insufficient permissions.
