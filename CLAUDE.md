# Tusk — Agent Onboarding

Fast, native, lightweight **Postgres-first database client**. Goal: replace the clunk of pgAdmin and the resource weight of JetBrains DataGrip. Tauri (system WebView, not Electron) + Rust + SolidJS. Launches sub-second, low RAM, ~5 MB installer.

This file is the source of truth for working in this repo. Keep it, `CHANGELOG.md`, and the code in sync.

## Stack

- **Shell:** Tauri v2 (system WebView2 / WKWebView — no bundled browser).
- **Frontend:** SolidJS + TypeScript + Vite + CodeMirror 6.
- **Backend:** Rust + `tokio-postgres` (text/simple protocol), `native-tls`, `keyring`.

## Build / run / verify

```sh
npm install                 # once
npm run tauri dev           # run the app (needs Rust + Node 20)

# Validate after edits (ALWAYS do this before claiming done):
cargo build --manifest-path src-tauri/Cargo.toml      # backend
npm run build                                         # frontend bundle
npx tsc --noEmit -p tsconfig.json                     # frontend types
npx vitest run                                        # pure-TS units (plan parsers, viz layouts)

# Cross-engine driver conformance (after touching driver.rs / a driver):
cargo test --manifest-path src-tauri/Cargo.toml --lib driver_conformance  # embedded (DuckDB+SQLite)
scripts/conformance.sh                                # + Postgres & MySQL via throwaway Docker containers
```

- **After Rust changes → tell the user to restart `npm run tauri dev`.** Frontend-only changes hot-reload.
- Installers are built in CI: push a `v*` tag → `.github/workflows/release.yml` builds mac (universal) + Windows (NSIS, per-user) and drafts a GitHub release. Don't cross-compile locally.
- **Built-in updater:** `tauri-plugin-updater` polls `releases/latest/download/latest.json` (published releases only — a draft is invisible to it). CI signs updater artifacts with the `TAURI_SIGNING_PRIVATE_KEY` repo secret (minisign key, empty password; pubkey lives in `tauri.conf.json` `plugins.updater`; keypair at `~/.tauri/tusk.key` on the dev machine — NEVER commit it). Frontend = `src/UpdateBadge.tsx` (bottom-right pill, both screens; silent on check failure). `createUpdaterArtifacts: true` in the bundle config; capabilities add `updater:default` + `process:allow-restart`.

## Conventions

- Update `CHANGELOG.md` (`[Unreleased]`) on every change.
- Run the three validate commands above after edits.
- Surfacing errors: `db.rs`'s `From<tokio_postgres::Error>` unwraps the real Postgres message (don't regress to bare "db error").
- Caveman chat style seen in history is a *session* preference (the `/caveman` skill), **not** a code/docs convention — write code, commits, and docs normally.

## Architecture

### Backend — `src-tauri/src/`
- **`lib.rs`** — Tauri app. `AppState` = connection registry (`HashMap<id, Arc<Mutex<ConnState>>>`). Commands thin over `c.backend` (driver-agnostic execution; see `driver.rs`): `connect`, `connect_profile`, `disconnect`, `list_profiles`, `save_profile`, `delete_profile`, `run_query` (streams via `Backend::run_single`), `capabilities`, `validate_sql` (editor server-lint — PREPARE-only, never executes), `fetch_more`, `list_schema` (now feeds **frontend autocomplete**, decoupled from the lazy tree), `db_tree` (shallow), `table_detail` (per-relation detail on expand), `object_ddl` (Copy DDL), `export_to_file`, `import_rows`. `ConnectResult` carries `read_only` so the UI gates mutating menu items. Plugin init (opener, dialog). `is_cursorable` / `is_read_only_stmt` / `is_prepareable` / `has_bind_params` / `db_error_diag` helpers. **All sidebar mutations reuse `run_query`** — no dedicated DDL-exec commands. `validate_sql` reuses `script::split` + `ensure_alive`, rolls back any open cursor first, runs in autocommit (a failing statement doesn't poison the next), skips DDL/COPY/`$1`-param statements, and maps Postgres' 1-based error position back into the statement. `export_to_file` now takes an `ExportOptions` payload + either an `sql` query (stream, scope=all) or inline `columns`+`rows` (scope=loaded). `cancel_operation` issues an **immediate** Postgres `CancelRequest` (via the client's `CancelToken`, over its own short connection built with `db::make_tls`) to interrupt the in-flight export/import; `AppState.cancels` holds `(CancelHandle, ConnectionConfig)` per connection (via `Backend::cancel_handle`), **armed by the operation after `ensure_alive`** (so the handle matches the live backend) and disarmed when it ends — kept outside the per-connection `AsyncMutex` (which the operation holds for its whole duration) so the cancel can reach it. `import_rows` runs `CREATE`+`COPY` in one transaction and rolls back on cancel/error (nothing half-created). `read_text_file`/`write_text_file` (tokio::fs) back the editor's Open/Save flow — no `tauri-plugin-fs`. `load_history`/`save_history` persist per-connection query history as JSON under `<app-config>/history/` (frontend `src/history/store.ts`; failures degrade to in-memory, never block a run). `list_functions` (per-driver callable-name catalog for the unknown-function lint; MySQL returns empty — no builtin catalog, partial lists false-positive). `table_relationships`/`schema_relationships` (→ **`relgraph.rs`**) return structured FK edges (`FkEdge` w/ ordered column lists — PG aggregates names with `chr(31)`/`\x1f` as a collision-proof separator, split in Rust) + ERD table summaries, enum-dispatched on all four engines, best-effort (empty results, never errors; DuckDB tries `duckdb_constraints()` structured columns then falls back to parsing `constraint_text`). `object_ddl` now calls `Backend::relation_ddl` — multi-engine DDL (PG `ddl.rs` reconstruction / SQLite `sqlite_master` + index DDL / MySQL `SHOW CREATE` / DuckDB `duckdb_tables()` best-effort) — so sidebar Copy DDL works everywhere. Capabilities adds `ddl`/`relationships`/`explain_analyze` (SQLite has no EXPLAIN ANALYZE). `validate_sql`'s prepareability check is a **skip-list** (`is_prepareable` skips known DDL/utility/transaction starters + psql `\meta`), so an unrecognized leading word (`SELCT …`) IS PREPAREd and yields a real parser diagnostic — don't revert it to an allow-list (that silently swallowed misspelled first keywords). `run_query`/`validate_sql`/`export_to_file` take an optional `search_path` (the console's active schema); `apply_search_path` runs `SET search_path TO <db::ident>, public` (or `RESET`) before exec/PREPARE/DECLARE — threaded into `exec_items` so it survives the reconnect-retry.
- **`driver.rs`** — **driver abstraction** (multi-DB). `Backend` enum — `Pg(PgConn{client,config,cursor_open})`, `Duck(DuckConn)`, `Sqlite(SqliteConn)` (the two embedded arms share the `Mutex<Connection>` + LIMIT/OFFSET pager pattern) — owns the execution surface: `run_single`(stream)/`fetch_page`/`run_script`/`apply_search_path`/`rollback_cursor`/`reopen`/`is_closed`/`cursor_open`/`cancel_handle`/`config`/`capabilities` + **introspection** (`build_tree`/`table_detail`/`list_tables`, the autocomplete list, now driver-dispatched). `driver::connect(config)` dispatches on `config.driver` ("postgres"|"duckdb"). `pg() -> Result<&Client>` is the **escape hatch** for still-PG-only paths (DDL reconstruction/export-stream/server-lint/import) — errors on DuckDB. `ConnState {backend, read_only}` lives here. `CancelHandle` (Pg=libpq cancel / Duck=`InterruptHandle`) + `Capabilities` (serialized; gates UI). **DuckDB specifics:** embedded (`duckdb` crate, `bundled`, **pinned `~1.4`** — the registry's `1.105xx` versions are DuckDB 1.5 *previews* that sort above 1.4.x and broke even `CURRENT_DATE - INTERVAL` binding; never loosen to `version = "1"`); `Connection` is `Send` but `!Sync` so it's wrapped in `Mutex` (else command futures aren't `Send`) — access via `DuckConn::lock()` (returns a `DuckGuard` derefing to `&Connection`). **Idle file-lock release:** a file-backed DuckDB holds an exclusive OS lock for its whole lifetime, so `conn` is `Mutex<Option<Connection>>` — `release_idle()` (called by lib.rs's `ConnGuard` Drop at the end of every command) drops the connection when nothing is streaming, freeing the lock; `ensure_alive`→`reopen` re-opens it lazily next command (so `is_closed()` returns true once released). `:memory:` keeps `keep_open=true` (closing loses data). The LIMIT/OFFSET pager re-derives each page from `stream_sql`, so release-then-reopen resumes paging. values rendered as text via `CAST(COLUMNS(*) AS VARCHAR)`; paging is LIMIT/OFFSET over `stream_sql` (no server cursor); **`column_names()` panics before the statement is executed** — `duck_query` calls `query()` first, then reads names from `rows.as_ref()`; introspection via `information_schema`. **ICU extension:** the bundled libduckdb does **NOT** compile ICU in, so `TIMESTAMPTZ` casts (e.g. `CAST(col AS DATE)`) fail with "Unimplemented type for cast" until the extension is downloaded into `~/.duckdb/extensions/<ver>/<platform>/`. `open_conn` fast-paths `LOAD icu` and, **on failure, runs `INSTALL icu` (one-time network fetch, cached on disk) then `LOAD` again** — on every connection, including reopens after idle release. Best-effort: cold + offline degrades to the cast error rather than failing the connection. Don't "simplify" this back to a bare `LOAD` — that only works on a machine whose extension cache was already warmed (e.g. by the DuckDB CLI), which is why `driver_conformance`'s `duckdb_timestamptz_cast_after_icu_load` passed for the author and failed everywhere else. `SET autoinstall_known_extensions`/`autoload_known_extensions` do **not** fix it — a cast never triggers autoload. **SQLite specifics:** `rusqlite` (`bundled`), same `Mutex<Connection>` + LIMIT/OFFSET pager; `ValueRef` (5 types) yields text per cell so no cast wrap; **no `information_schema`** → `list_tables`/`build_tree`/`table_detail` use `sqlite_master` + `PRAGMA table_info` (single `main` schema); cancel = `CancelHandle::None`. **MySQL specifics:** `mysql_async` with a `Pool` (Send+Sync+Clone → no `!Sync` problem; each LIMIT/OFFSET page is an independent pooled query); `mysql_run` returns (cols, text-rows, affected) — `Value` → text per cell; introspection via `information_schema` (databases-as-schemas); sslmode → `SslOpts` (accept-invalid unless verify-ca/full); DDL non-transactional. **MySQL forbids duplicate column names in a derived table (error 1060)** — so the LIMIT/OFFSET pager (`mysql_page`) tries the `SELECT * FROM (<q>) _tusk` wrap and, on 1060, falls back to appending `LIMIT/OFFSET` (streams a result with duplicate output columns, e.g. a join sharing a column). The grid's frontend sort/filter wrap still needs unique column names on MySQL (known limitation). **Conformance:** all four engines are exercised by `driver_conformance.rs` (run via `scripts/conformance.sh`, which spins up PG+MySQL Docker containers) — covers NULL/unicode/quotes/paging-boundaries/large-values/introspection/weird-identifiers/read-only. Adding a driver = a new enum arm (the compiler flags every non-exhaustive `match`) **+ extend the conformance battery**.
- **`db.rs`** — `ConnectionConfig`, `AppError` (rich error surfacing), `open()` (connect w/ TLS via `make_tls`, sslmode, `default_transaction_read_only`), `make_tls`/`ssl_mode_of`, `collect_rows()` (turns `simple_query` messages into `(columns, rows)` where **every value is text or NULL** — no per-type mapping, handles any type; reads `SimpleQueryMessage::RowDescription` so a **zero-row result still carries its column names**, i.e. an empty SELECT shows its headers), `ident`/`create_table_text`/`copy_rows` for import, `CURSOR_NAME`. (`ConnState` moved to `driver.rs`.)
- **`profiles.rs`** — saved connections. Metadata → `connections.json` in the app config dir; **password → OS keychain** (`keyring`, per-OS features), never plaintext, never sent to the frontend. `upsert`/`delete`/`load_all`/`get_password`.
- **`script.rs`** — SQL **script runner**. `split()` is a byte-level lexer handling `--` / `/* */` comments, `'…'` / `"…"` quotes, **dollar-quotes** (`$tag$`, distinguishes `$1`), and `COPY … FROM stdin` + `\.` data blocks. `run()` executes items in one transaction (rolls back + reports the failing statement); COPY blocks go through `copy_in`. `effective_start()` skips leading comments (so a COPY preceded by a `--` block is still detected).
- **`export.rs`** — **options-driven export**. `ExportOptions` (serde mirror of `src/export.ts`) drives every formatter: delimiter/quote-mode/quoteChar/null-repr/header/line-ending/BOM/column-projection + SQL (table, multi-row INSERT, CREATE) + xlsx (sheet, bold header, autofilter, freeze). `run_export_query` streams a query via a server-side cursor (10k batches, constant memory for text via `TextEmit`, lazy file create → empty result writes nothing); on cancel/error it `ROLLBACK`s and **deletes the partial file** (xlsx writes only at finish, so nothing on disk to remove); `run_export_rows` formats inline (loaded) rows. **Excel** (`XlsxSink`, `rust_xlsxwriter` w/ the `constant_memory` feature) streams each worksheet's rows to a per-sheet **tempfile** (`add_worksheet_with_constant_memory`) so RAM stays flat even for hundreds of thousands of rows — requires writing rows strictly top-to-bottom and per-row formatting only on the current row (the bold header is row 0; **autofilter is sealed per-sheet while it's still the current sheet** via `seal_current_sheet`, never reaching back into a flushed sheet). The destination `.xlsx` is still only written at `wb.save()` on finish (the tempfiles are rust_xlsxwriter-internal, cleaned up on drop), so the cancel/error path still has no partial destination file to remove. **Rolls into a new sheet every 1,048,576 rows**. The TS clipboard path (`formats.ts` `formatWithOptions`) must match these formatters byte-for-byte.
- **`tree.rs`** — introspection. `build_shallow()` = fast connect-time tree (`DbTree { database, databases, schemas[] }`, each schema's tables/views/sequences/functions as **name+kind stubs** + table comment; includes empty schemas). `RelStub` also carries `rows: Option<i64>` (planner `reltuples::bigint`; `-1`/never-analyzed → `None`) + `size: Option<String>` (`pg_size_pretty(pg_total_relation_size)` for tables/matviews only, via a relkind-guarded CASE) — non-PG drivers construct stubs with `None`. `table_detail(schema, name)` = lazy per-relation columns (with `is_pk`/`is_fk`/nullable/default/**comment**), indexes, constraints, **triggers** (`pg_trigger`/`pg_get_triggerdef`, `NOT tgisinternal` so FK-internal triggers stay hidden; non-PG drivers return `vec![]`) — resolves the relation's OID via a **parameterized** query, then drives detail queries by that trusted integer.
- **`ai.rs`** — AI provider proxy. Commands `ai_save_key`/`ai_has_key`/`ai_clear_key` (key → OS keychain via `keyring`, service `tusk-ai`, account = **provider id**; **never returned to the frontend**) + `ai_chat(req, Channel<AiEvent>)` which streams completions: builds the request (`build_request`), POSTs via `reqwest` (rustls), parses line-based SSE (`data:` lines → JSON → `parse_sse_line` → `Frame`), emits `AiEvent::{Delta,Done{truncated},Cancelled,Error}` over the channel (always resolves Ok; failures are Error events). **Dispatch is on `Wire`, NEVER on the provider name** — `Wire::{Anthropic,Gemini,Openai,Responses}` picks the request/response shape; the provider is just a keychain account + a base URL, both supplied by the frontend registry (`src/ai/providers.ts`). A gateway may use a **different wire per model** (both OpenCodes do), so the wire rides on the request, not the provider. So OpenRouter/Groq/OpenCode/Ollama/DeepSeek all ride the `Openai` arm and adding one is a registry row, not an arm here. `AiRequest.wire` is `Option<String>` — absent on pre-registry configs, where `Wire::legacy_for_provider` derives it from the provider name (the three original providers *were* their own wire). **Each wire has its own path AND its own auth header** (all probed against OpenCode, which serves all four): `Anthropic` = `x-api-key` + `anthropic-version`, `{base}/v1/messages`, `content_block_delta` (a Bearer header is *also* sent when `provider != "anthropic"` for proxies that want it; harmless — unknown auth headers are ignored, yielding "Missing API key" not a 400). `Openai` = `Authorization: Bearer`, `{base}/v1/chat/completions`, `choices/0/delta/content`; the Authorization header is **omitted entirely when the key is empty** (an empty `Bearer ` trips local servers). `Responses` = Bearer, `{base}/v1/responses`, body uses `input`/`instructions`/`max_output_tokens`, typed SSE events (`response.output_text.delta` for text — **NOT** `response.output_text.done`, which repeats the whole text and would duplicate the reply; `response.completed`/`response.incomplete` are terminal, there is no `[DONE]`). `Gemini` = **`x-goog-api-key` header** (NOT `?key=` — Google takes both, Zen only the header), `{base}/models/{model}:streamGenerateContent?alt=sse`. `allow_no_key` lets keyless local servers past `get_key`. **`base_url` is the prefix the wire appends to — usually before `/v1`** (hence `https://api.groq.com/openai`, not `.../openai/v1`); the **gemini wire is the exception**, its base carries the version segment (`…/v1beta`, or `…/zen/v1` on OpenCode), and `gemini_base()` heals a legacy path-less base by appending `/v1beta`. An SSE line is parsed into a **`Frame` struct, not an enum** (`delta`/`finish`/`error`/`done` — Gemini's last chunk carries text AND `finishReason`, so an enum would drop one): `extract_delta` + **`extract_error`** (anthropic `type:"error"`, top-level `error` object, gemini `promptFeedback.blockReason`; `"error": null` is NOT an error — vLLM/LiteLLM stamp it on every frame) + **`extract_finish`** → `classify_finish` → `Finish::{Normal,Truncated,Aborted}`. `stream_attempt` (one HTTP try) / `complete_with_retry` (3 attempts, 400/800 ms backoff on `retryable_status`/`retryable_msg`) / `complete_one_shot` (Slack; buffered, so it replays freely, and an empty response is an **error**) are the three layers. **Cancel:** `AiCancels` (managed state, `Mutex<HashMap<requestId, oneshot::Sender>>`, kept out of every connection lock) + the `ai_cancel` command; `ai_chat` registers a receiver under `req.requestId` behind a `CancelGuard` (Drop-unregisters on every exit path) and `tokio::select!`s it against both `builder.send()` and each `stream.next()`. The model only proposes; running SQL is always an explicit user action. **`sample_rows`** (in `lib.rs`, backed by `Backend::sample_rows`) feeds the assistant a few read-only sample rows per relevant table for grounding — runs without rolling back the streaming cursor.
- **`slack/`** — **desktop-hosted Slack bot** (v0.7.0; Socket Mode = outbound WSS + Web API over reqwest — no server, no public endpoint; **bring-your-own Slack app**, manifest + guide in `docs/slack-setup.md` — never ship a shared app, internal apps keep full Tier-3 API access under Slack's 2025 non-Marketplace limits). `socket.rs` — tokio-tungstenite client: mints the wss URL via `apps.connections.open` (Bearer xapp, `connections:write`), **acks every envelope immediately** (`{"envelope_id"}`, 3s deadline — work happens after ack), **dedupes by `event_id`** (at-least-once delivery), drops own-bot (`bot_id`) + `subtype`d events, strips `<@…>` mentions, reconnects w/ backoff + on `disconnect{refresh_requested}`. `processor.rs` — sequential event loop (= one query at a time): question → schema/perms/samples under the conn lock (released before the AI call) → `ai::complete_one_shot` → **single read-only SELECT gate** (`script::split` len 1 + `is_read_only_stmt`, checked at proposal AND execution) → proposal card; on approve: `SELECT * FROM (…) _tusk LIMIT cap+1` wrap (MySQL 1060 → append-LIMIT fallback), **buffered `run_single(cursorable=false)` — NEVER the shared `tusk_cur`**, `tokio::time::timeout` + **server-side cancel via the armed CancelHandle**, `BEGIN READ ONLY` wrap on PG only when no UI cursor txn is open; result → inline table / CSV / XLSX / locally rendered chart PNG, **plus "Export as… CSV/Excel/JSON/Markdown" buttons on every result** (`ResultStore` — 15-min TTL, 8-result cap; a click reformats via `export_rows_to_bytes` and uploads in-thread — not requester-gated, the data is already channel-visible); emits `slack:executed` → frontend records history with a `-- [Slack]` marker. `chart.rs` — **fully local chart rendering** (plotters 0.3.7 → RGB buffer → `png` crate; line / grouped-bar (manual Rectangles — plotters has no grouped Histogram) / scatter / pie): an EXPLICIT user chart request arrives as an AI-emitted ```chart JSON block (`ChartSpec`: type/x/series/title/xLabel/yLabel — prompt contract in `context.rs`) parsed by `ChartSpec::parse`, stored on the proposal, and **honored over the format heuristic** (unrenderable → note + fall back to table/file); the auto-heuristic (`format::auto_chart_spec`, date+numeric) rides the same renderer, gated by `chartsEnabled` (default ON — nothing leaves the machine). **Font gotchas:** text renders via plotters' `ab_glyph` backend off the EMBEDDED `assets/JetBrainsMono-Regular.ttf` (OFL) registered once as "sans-serif" — an unregistered family is a hard error not a fallback, and plotters' default `ttf` feature silently WINS over `ab_glyph`, so the dep must stay `default-features = false`. Caps: 400 points, 12 pie slices. `context.rs` — **PARITY PAIR with `src/ai/context.ts`** (budgets/relevance/samples must match; unit-tested; `extract_sql_blocks` skips ```chart-tagged fences). `api.rs` (postMessage/update/postEphemeral/`conversations.replies`/3-step external upload — `files.upload` is sunset). `blocks.rs` (Block Kit builders; sections truncated under the 3000-char cap; `chat.update` always sends full blocks — text-only strips them). `approval.rs` (in-memory proposal + result stores, 5-min proposal TTL sweep; only the requester may approve). `config.rs` (`slack.json` + tokens in keychain service `tusk-slack`; **AI provider/model mirrored from frontend localStorage at save time** — Rust can't read it). `mod.rs` (`SlackRuntime` managed state; `start`/`stop`; autostart in `.setup()` when enabled). `AppState.active_conn_id` (set by `register`, cleared on disconnect) picks the bot's connection. Commands: `slack_load_config`/`slack_save_config`/`slack_clear_tokens`/`slack_start`/`slack_stop`/`slack_status`/`slack_test`. Supporting additions: `ai::complete_one_shot` (non-streaming sibling of `ai_chat`, accumulates the same SSE), `export::export_rows_to_bytes` (tempfile-backed in-memory export for attachments). **`run()` installs the ring rustls CryptoProvider at startup** — reqwest(ring) + tokio-tungstenite(aws-lc-rs default) both in the graph means rustls has NO default provider and panics at TLS-config build otherwise; don't remove it, and keep the direct `rustls` dep on `ring`.
- **`perms.rs`** — Postgres permission model. `collect(client)` → `Permissions` (the role's **effective** privileges via `has_*_privilege`, accounting for membership/`PUBLIC`/ownership): role attrs (superuser/createdb/createrole), per-schema CREATE/USAGE+owner, per-relation SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER+owner (one `pg_class` scan), CREATE-on-current-db. `Backend::permissions()` → PG delegates here, others return `Permissions::unrestricted()` (`enforced:false`). Exposed by the `permissions` command; frontend gates sidebar DDL on it. **Bare `has_*_privilege()` bools come back `"t"`/`"f"` over the text protocol — never `::text`-cast them.**
- **`ddl.rs`** — `object_ddl(kind, schema, name)` reconstructs runnable `CREATE` DDL from `pg_catalog` (pg_dump-style): tables (identity/generated/serial defaults; PK/unique/check inline; **FKs as trailing ALTERs**; plain indexes only — constraint-backed skipped; table+column comments), views/matviews (`pg_get_viewdef`), functions (`pg_get_functiondef`, overloads; aggregates/window flagged via `prokind`), sequences (`pg_sequences`). User input bound as params, then by OID. Out of scope: partitions, inheritance, RLS, triggers, storage params, tablespaces, collations.
- **`main.rs`** — `tusk_lib::run()`.

### Frontend — `src/`
- **`App.tsx`** — everything UI. Connect screen (saved-profile list + form) with a **driver picker** (`DRIVERS` = PG/DuckDB live, SQLite/MySQL staged): DuckDB swaps host/port/SSL for a file path + Browse (blank = `:memory:`), connects ad-hoc (`driver`+`path` in the config; profiles stay PG). The **brand emoji adapts to the driver** (`driverMascot`: 🐘🦆🪶🐬) on the card + topbar + the **OS window title** (a `createEffect` calls `getCurrentWindow().setTitle` on conn/caps change — needs `core:window:allow-set-title` in `capabilities/default.json`). On connect, `afterConnect` fetches `capabilities` into `caps()`; the UI **gates** the search-path selector / Import / Export on `caps()?.searchPath/bulkCopy/export` (so DuckDB doesn't show PG-only actions). Workspace: topbar, **resizable** sidebar (`<Tree>` + **object filter** box), **tabbed editor** + **resizable** editor/results split, virtualized result grid, **Import** modal. The editor toolbar sits ABOVE the editor (under the tab strip) and is **responsive via `@container editorpane` queries** (hint drops → text actions collapse into a ⋯ overflow menu fed by `openToolbarOverflow`/`explainMenuItems` → font/wrap icons hide); the **result toolbar above the output** owns Plan/Grid toggle, Load all/streaming, pending-edit controls, copy-headers, **Export…**, and elapsed ms; the footer statusbar is just status text + cursor info. **Editor tabs** (`src/tabs.ts` `Tab`): each owns a `sql` buffer, `filePath`/`dirty`, and a `ResultSnapshot` (the result grid is per-tab); App-level `columns()/rows()/done()/status()/setStatus/setRunErr` are now accessors over `activeTab().result` (so the grid JSX is unchanged). The **result grid is `ResultGrid.tsx`** (extracted); App owns data/streaming/cursor + the global `ContextMenu`/`cellView` and passes accessors + callbacks (`onSortFilter`→`executeQuery(wrapped,…,"wrapped")`, `onLoadMore`→`loadMore`, `onMenu`→`setMenu`, `onViewValue`→`cellView`). `executeQuery(sql, base, mode)` is the shared runner: `mode:"base"` records `baseQuery` + resets the grid view's sorts/filters (fresh `gridView` if the column set changed, but `filterRowOpen` visibility is preserved), `mode:"wrapped"` keeps it; **re-running the SAME query text with active sort/filter rules re-streams it wrapped** (`runTextNow` matches `base` against the prior `baseQuery` + `hasViewRules` → carries the rules over instead of resetting). ## Gotchas (read before debugging)

- **Values are text.** `simple_query` returns everything as strings; `NULL` = `None`/`null`. Don't assume typed values.
- **Single statement vs script.** A single read statement streams to the grid via a server-side cursor. For **multiple statements**, if the *last* one is a cursorable read, `exec_items` runs the leading statements as a transactional script and then **streams the last statement** to the grid (so its result shows, with pagination) — note the leading writes commit *before* the trailing read, so a failing trailing SELECT no longer rolls them back. Otherwise (last is a write/COPY) it runs everything as a transactional script and reports a summary (no grid). The trailing-read stream heals a dropped connection in place so `run_query`'s outer retry can't replay the committed leading statements. Routing is in `exec_items` via `script::split`. **The frontend Run chooser:** hitting Run (button or ⌘/Ctrl+Enter) with the cursor inside one of several statements and nothing selected opens a small popover to run the whole file or just that block (`runChoice`/`chooseRun` in `App.tsx`; a selection or a single-statement buffer runs without prompting). A multi-statement run stores a non-wrappable `baseQuery` (`""`) so grid sort/filter is disabled (it can't wrap a script).
- **COPY detection ignores leading comments** (`effective_start`). pg_dump prefixes every COPY with a `--` block; missing this sends COPY to `batch_execute` → `CopyInResponse` → "unexpected message from server".
- **Keychain in dev:** unsigned `tauri dev` builds re-prompt / invalidate saved passwords across rebuilds (macOS ties items to the code signature). Seamless in signed release builds. `keyring` features are per-OS in `Cargo.toml`.
- **TLS:** `native-tls` (SecureTransport on mac, SChannel on Windows; needs OpenSSL on Linux). `sslmode`: `disable` | `prefer` (default) | `require` (encrypt, no cert verify) | `verify-full` (verify).
- **Read-only mode:** server `SET default_transaction_read_only = on` **and** a client-side write/DDL guard. The sidebar additionally disables mutating menu items (defense-in-depth) via `ConnectResult.read_only`.
- **Dropped connections auto-recover; query duration is never capped.** `ConnState` keeps the `ConnectionConfig` (incl. password — server-side only, never sent to the frontend); every query command calls `ensure_alive` (re-opens when `client.is_closed()`), and `run_query` retries once if a query dies mid-flight. So idle-timeout / server-restart heals on the next action. `db::open` sets a **10s `connect_timeout`** + **aggressive TCP keepalives** (`keepalives_idle` 5s, `keepalives_interval` 2s, `keepalives_retries` 3, `tcp_user_timeout` 15s) so a genuinely dead connection surfaces as `is_closed` in ~10-15s and the in-flight query errors — but a slow live query keeps getting ACKs and runs unbounded (no `tokio::time::timeout`). A re-open drops any open streaming cursor (`cursor_open` reset) — so `fetch_more` checks `was_streaming && !cursor_open` after `ensure_alive` and returns an **error** ("connection dropped mid-stream — … Re-run the query …") rather than a silent `done:true` that would present a truncated result as complete. The frontend `loadMore` catch surfaces any fetch error in the result error banner (over the rows fetched so far) + a `streaming stopped — …` status, then stops paging (don't regress either back to console-only/silent-done). The Run button shows a live elapsed counter (`runMs` + `fmtDur`).
- **Autocomplete corrupting dollar-quotes** was caused by Enter-accept **combined with `$` being a completion token** (so `$tag$` delimiters were offered and replaced on accept). The fix that matters is keeping **`$` out of completion tokens** — with that in place, Enter-accept is safe and is now enabled (Enter accepts like Tab; `acceptCompletion` no-ops to a newline when no popup is open). Don't re-add `$` to completion tokens.
- **Lazy tree ⇒ autocomplete uses `list_schema`, not the tree.** The shallow `db_tree` no longer carries columns, so autocomplete is fed by `list_schema` (one query). Expanding a node fetches `table_detail` (cached); after DDL, `runDDL`→`loadSchema` refetches the shallow tree + `list_schema` and re-fetches already-open details.
- **Sidebar DDL must stay single-statement where it matters.** `CREATE/DROP DATABASE` can't run in a transaction — keep them one statement (multi-statement input routes to `script::run`, which wraps in `BEGIN`). Builders in `sql/ddl.ts` emit one statement each (comma-separated ALTER actions, not `;`-joined); multi-statement cases (duplicate-with-data, column edit + rename) are intentionally table-only.
- **Copy DDL is reconstructed, not pg_dump.** Driven by OID; constraint-backed indexes are skipped and FKs deferred to trailing ALTERs so replay doesn't error. Partitions/inheritance/RLS/triggers/storage are out of scope (see `ddl.rs`).
- **Quoting parity + dialect.** `sql/ident.ts` `ident` is **dialect-aware** (`setSqlDialect`): MySQL = backticks `` `x` ``, everyone else = double `"x"`; literals are `'…'` for all. Set once per connection by an App effect off `activeDialect()` (the app is single-connection, so a module var avoids threading a dialect arg through scaffolds/grid-filters/DDL builders). For **Postgres** it matches Rust `db::ident` — and `db::ident` is only used on PG-only backend paths (import / DDL recon), so the parity that matters is PG↔PG. **Editor dialect follows the connected driver**, not a manual selector: `activeDialect = conn() ? driverDialect(caps().kind) : prefs().dialect` (DuckDB → `postgres` dialect; the old toolbar dialect `<select>` was removed). Always quote identifiers in generated SQL.
- **Never `::text`-cast a boolean in catalog queries.** `collect_rows` reads the text protocol: a *bare* bool comes back `"t"`/`"f"`, but `bool::text` (e.g. `i.indisunique::text`, `(con.oid IS NOT NULL)::text`) comes back `"true"`/`"false"`. The code compares against `"t"`, so a cast silently makes every check false. Select the bare bool (`i.indisunique`, `(NOT a.attnotnull)`). Char columns (`relkind`, `attidentity`, `contype`) DO need `::text`.
- **`editor/lexer.ts` must mirror `script.rs`.** Auto-fold, both client lints, and the formatter's dollar-quote carve-out all classify spans via this lexer — it must match `split`/`dollar_tag_end` byte-for-byte (incl. `$1` = param, not a tag). It's UI-only: it skips psql `\meta` + COPY-data handling that `script::split` does, so server-lint statement *indices* can diverge from the TS `splitStatements` on a script containing a `COPY … FROM stdin` block (rare; typed queries align).
- **Auto-fold is display-only.** It replaces ranges with widget decorations; the document text is never modified, so `getRunText`/`getDoc`/export always return the full expanded query. Folds recompute on doc-change (candidate geometry) and on every selection move (cursor in a range → expanded). Don't reach for `@codemirror/language` fold state for this — that's the separate *manual* fold gutter (`foldBasics.ts`).
- **One cursor, many tabs.** There's a single server-side cursor per connection (`tusk_cur`), so only one tab can stream at a time. `doRun` frees another tab's cursor and marks its snapshot `done` before running; `cursorOwnerTabId` gates `loadMore` so scrolling a non-owning tab never `FETCH`es the wrong cursor. Any sidebar command also rolls the cursor back — the owner tab's stream just stops (snapshot frozen). Per-tab editor state (undo/cursor/fold) lives in a `Map<tabId,EditorState>` in `SqlEditor.tsx`; **`view.setState()` replaces all state incl. compartments**, so every tab state is built via the shared `buildExtensions` (seeded with the current dialect/theme/fold), and the guarded value-effect skips during a swap (`props.tabId === curTabId`) so it can't clobber the outgoing tab.
- **Grid `<For>` bodies must read via accessors, not `const`.** In `ResultGrid.tsx` the windows iterate index ranges (`range(visCols…)`); inside, use `const oi = () => displayCols()[k]` / `const val = () => rows()[r]?.[oi()]` (functions), NOT `const oi = displayCols()[k]`. A plain const is captured once at item-render; since the `For` key (the index) doesn't change on a sort re-run (rows replaced) or reorder (displayCols changed) with the same window, captured consts go stale and cells show old data / the sort glyph never appears. Read reactively in the JSX. The grid's frozen header/gutter are transform panes (not sticky); a new query bumps `result.epoch` so the grid resets scroll (vs a tab switch, which restores it) — keyed on `${tabId}:${epoch}`. **That key MUST be a `createMemo`, not a plain `() =>` function.** `on()` re-runs its callback whenever a tracked dep *notifies*, not only on value change, and `epoch` reads through App's `activeTab()` memo whose identity changes on every `patchTab`/`patchResult` — so a plain key fired the reset (scrollTop→0 + selection clear) on every row append / resize / reorder / hide, making those feel broken. The memo dedupes by string so the reset runs only on a real tab switch or epoch bump. **Scroll never writes to reactive state**: `onScroll` updates only the local `scrollTop`/`scrollLeft` signals (only the window memos depend on them) + a non-reactive per-tab `scrollMem` Map. Persisting scroll into `gridView`/`setView` per frame rebuilds the tabs array and cascades a full-App recompute every frame — it froze/crashed large tables. Keep scroll out of `view`.
- **Active schema is per-tab, applied per run.** `Tab.searchSchema` (null = default) drives `SET search_path` on the *shared* session — so it must be re-applied (or `RESET`) on every run_query/validate/export, never assumed sticky. Autocomplete labels a table bare when its schema is `public` or the active schema (`makeSqlCompletion`'s 3rd `getActiveSchema` arg). Export scope=all uses the *producing* tab's schema via the `exportSrc` snapshot. Schema-lint still resolves bare names via `byBare` (no active-schema preference yet — minor, deferred). **Generated query scaffolds** (`genSelect`/`genInsert`/`genUpdate`, `runTable`) use `qualifyIn(schema, name, activeSchema)` — drops the schema prefix when it matches the tab's active schema — and open a **new tab** via `openGeneratedTab` (schema set to the relation's) rather than clobbering the active tab. DDL builders keep using `qualify` (always explicit — never depend on search_path for drop/alter/rename).
- **Native widgets need `color-scheme`, not CSS colors.** The `<select>` **popup**, scrollbars, and checkboxes are painted by the WebView, not by our CSS — styling the select box (`background: var(--bg)`) does nothing for the popup. `:root` declares `color-scheme: dark` and `:root[data-mode="light"]` declares `light`; without it the popup renders light while `<option>` inherits the dark theme's near-white `--text` (white on white). Explicit `select option, select optgroup` colors are belt-and-braces for webkit2gtk. Keep `color-scheme` keyed to `data-mode`, not to `data-theme` — polarity, not palette.
- **Lint squiggles: SVG background, not `text-decoration: wavy`.** WKWebView (the macOS Tauri runtime) renders `text-decoration-style: wavy` unreliably. `.cm-lintRange-{error,warning,info}` in `App.css` use a repeating inline-SVG wavy underline (CodeMirror's own mechanism), recolored. Don't set `background: none` on those (it removes the squiggle), and don't rely on `wavy` text-decoration. Lint diagnostics are generated by the client (heuristic+schema) + server linters regardless — this is purely the *painting*.
- **Export parity + scope.** `export_to_file` streams a query (scope=all) or formats inline rows (scope=loaded); the clipboard path uses TS `formatWithOptions` which must stay byte-identical to `export.rs` (delimiter/quote/null/header/column-projection/line-ending) — same parity class as `ident.ts`↔`db::ident`. The Export dialog reads a **frozen `exportSrc` snapshot**, not live `columns()/lastQuery()`. xlsx is file-only (no clipboard) and buffers the whole workbook (rolls into new sheets past 1,048,576 rows). **Cancel only interrupts a running DB query** (scope=all stream, import COPY) — `cancel_operation` sends a Postgres `CancelRequest`; it can't abort the in-memory `run_export_rows`/clipboard formatting loop (no DB query running), but those are fast. The cancel error message contains "cancel…"; the dialogs map it to "… cancelled — rolled back". Both dialogs lock their controls via a `<fieldset disabled>` while busy (only the Cancel button stays live; the ✕/overlay-dismiss are gated by `Dialog`'s `dismissable` prop).
- **`validate_sql` never executes.** It only `PREPARE`s (parse+plan) then `DEALLOCATE`s, in autocommit, after rolling back any streaming cursor. It skips DDL/COPY and `$1`/`:name`-param statements (PREPARE can't infer their types; `has_bind_params` is a byte scanner masking strings/comments/dollar-quotes). The frontend skips it while `running()` (shared connection lock) and when the `serverLint` pref is off. Position math: PG's 1-based offset is into `PREPARE … AS {stmt}` → backend subtracts the prefix (chars), frontend adds the statement's leading-whitespace offset.
- **Providers are data; wires are code.** `ai.rs` knows three wire shapes and nothing else; `src/ai/providers.ts` knows every provider. Adding OpenRouter/Groq/DeepSeek/a proxy = a registry row. Three traps: (1) **provider id == OS-keychain account** — renaming an id orphans every user's saved key for it; (2) **`baseUrl` is the prefix before `/v1`** because each wire appends its own path (`{base}/v1/chat/completions`, `{base}/v1/messages`, `{base}/v1/models`) — Groq's base therefore ends in `/openai`, OpenRouter's in `/api`; (3) the registry lives in TS, so anything Rust-side that needs it (**`slack.json`**) gets the **resolved** `aiWire` + `aiBaseUrl` mirrored in at save time — a new provider needs a Settings → Slack re-save, and an absent `aiWire` falls back to deriving from `aiProvider`. Curated model lists are fallbacks for a failed catalog fetch: never list a model with a known shutdown date (guarded by `providers.test.ts`), and prefer `models: []` (live-catalog-only) for routers whose ids are vendor-namespaced.
- **An SSE frame that isn't a delta is not nothing.** Providers report failures *inside* a `200 OK` stream (Anthropic `{"type":"error"}` for overloaded/rate-limit, OpenAI `{"error":{…}}`, Gemini `promptFeedback.blockReason`) and report truncation via a stop reason (`max_tokens`/`length`/`MAX_TOKENS`). The original parser matched only the delta pointer and treated everything else as `Ignore`, so a mid-stream failure ended the loop and emitted **`Done`** — the UI showed a truncated reply as a finished one, and Slack turned a half-written (unclosed ```sql fence) reply into the hardcoded "I can't help with that from Slack — try the Tusk desktop editor," blaming the user's question for a provider outage. When adding a provider, wire up **all three** of `extract_delta`/`extract_error`/`extract_finish` and add its frames to `ai.rs`'s tests; a provider whose errors you don't parse fails silently, which is strictly worse than failing loudly. Two traps: `"error": null` on every frame (vLLM/LiteLLM) is not an error, and a frame can carry a delta *and* a finish reason at once (Gemini's last chunk) — hence `Frame` is a struct, not an enum. Retry only replays when nothing has been painted yet (`soft_fail(msg, emitted && partial_is_fatal)`); the streaming path must never re-stream over visible text.
- **Slack bot: six invariants.** (1) **No query runs without an Approve click** — the button is the single gate; the AI only proposes. (2) **Never the shared cursor** — Slack execution is `run_single(cursorable=false)` on a LIMIT-capped wrap; opening `tusk_cur` would clobber a live UI stream. (3) **Ack-then-work + dedupe** — Socket Mode envelopes are acked within 3s BEFORE AI/query work, and `event_id`s are deduped (at-least-once delivery; a retry must not double-post a proposal). (4) **Timeout cancels server-side** — `tokio::time::timeout` alone abandons only the client future; the armed `CancelHandle` fires a real CancelRequest. (5) **`slack/context.rs` ↔ `src/ai/context.ts` are a parity pair** (budgets/relevance/sample formatting/**FK rendering + the `fks_known` tri-state**) — change both together; `build_system_prompt` takes `&[FkEdge]` + `fks_known`, and `processor.rs` fetches `schema_relationships` for the focus schemas (+`public`, capped at 3) under the conn lock. **Known Slack limitations (v1, documented):** the query timeout only preempts the async network drivers (PG/MySQL) — DuckDB/SQLite `run_single` is synchronous, so a pathological embedded query holds the connection lock until it finishes (same as the UI's own run on embedded; the timeout message says "cancel requested; the server may still be finishing it"). Config (allowlists/timeout/caps/policy/AI provider) is reloaded per-event, so Save applies on the next question without a restart. The bot targets `active_conn_id` (last-registered wins); a proposal approved after the UI switches connections runs against the new one (read-only gates still apply). (6) **Mutations can NEVER run from Slack — layered, never prompt-only:** `validate_read_only` (checked at proposal AND execution, AI SQL is never trusted) = `script::split` single-statement + `is_read_only_stmt` prefix + `find_mutation_word` — a masked scan (strings/comments/dollar-quotes/quoted idents blanked) that word-boundary-matches insert/update/delete/merge/drop/alter/truncate/create/grant/revoke ANYWHERE in the statement (catches writable CTEs like `WITH d AS (DELETE …) SELECT`, smuggled DDL, `FOR UPDATE`/`FOR SHARE` row locks); plus the `SELECT * FROM (…) LIMIT` wrap and PG `BEGIN READ ONLY`. A false positive (bare column literally named `delete`) degrades to "run it in the Tusk editor" — that's the correct trade; never loosen the scan to fix one. The `destructivePolicy` setting ("proposeReadonly" default | "refuse") only shapes the AI's REPLY to destructive asks (preview-SELECT vs refusal relayed as a plain reply — `Proposal::Reply`); it gates nothing, the scan does. Also: tokens never leave the keychain (`tusk-slack`); the bot reads the AI provider/model from `slack.json` (mirrored from localStorage on save), not from the frontend; config changes while running need a bot restart (toggle off/on); `run()` must keep installing the ring CryptoProvider (dual rustls providers in the graph = runtime panic).
- **In-grid editing: pending overlays, never mutations.** `Tab.pending` (`tabs.ts` `PendingEdits` — sparse `cells`/`deletes`/`inserts`) is ephemeral, **never persisted, never in `gridView`, never in the grid's `resultKey` epoch memo** (it would fire scroll/selection resets on every keystroke). Snapshot rows stay untouched; commit WHERE clauses read the ORIGINAL values, so an edited PK still locates its row. `executeQuery` confirms + clears pending before any re-run/sort/filter (rows it indexes into are replaced); `loadMore` is safe (append-only — `cells`/`deletes` index by LOADED row and stay valid; inserts render at the TOP so streaming more rows never disturbs them). Paste (⌘/Ctrl+V) funnels through `onPaste`→`planPaste`/`mergePaste`; it only ever appends inserts or edits existing rows, so the same index-stability holds. Commit (`doCommit`) invokes `run_query` **directly** with `searchPath: null` (statements are fully qualified) — multi-statement scripts are transactional on every driver (B0), so a failed commit rolls back wholesale and pending is kept. App's `editCtx` memo = `editTarget` → missing `table_detail` requested via a `want` effect → `editPlan`; DuckDB PK info comes from `pragma_table_info` in `duck_table_detail` (information_schema has none). No optimistic-concurrency check (last write wins) — documented, deferred. **SAFETY INVARIANT — plain select lists only:** `editTarget` rejects any select item that isn't `*`, `t.*`, `col`, or `t.col` (no expressions, functions, CASE, literals, or aliases — `plainSelectList`, depth-tracked to find the top-level FROM). An expression or alias colliding with a column name (`SELECT id*2 AS id …`, `SELECT email AS id …`) would make the commit's PK WHERE clause target the **wrong row** — never loosen this check; the same hazard is why WITH/TABLE/VALUES forms reject. Defense-in-depth: the grid's `canEditCol` + App's `onEditCell` both refuse non-`isTableCol` columns, `selectedRowIndices` never expands a cols-mode selection into row deletes (it spans ALL rows), `openCommit` refuses an empty script, and PG perms (no update/insert/delete/owner) disable editing up front. Grid copy reads through the `cellVal` overlay **plus the bool mapping** (`copyVal` — boolean-detected columns copy as the displayed TRUE/FALSE words, not the driver's `t`/`f`/`0`/`1` tokens; "View value…" stays raw) so copied text matches what's displayed.
