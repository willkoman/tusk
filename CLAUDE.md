# Tusk — Agent Onboarding

Fast, native, lightweight **Postgres-first database client**. Goal: replace the clunk of pgAdmin and the resource weight of JetBrains DataGrip. Tauri (system WebView, not Electron) + Rust + SolidJS. Launches sub-second, low RAM, ~5 MB installer.

This file is the source of truth for working in this repo. Keep it, `CHANGELOG.md`, and the code in sync.

## Stack

- **Shell:** Tauri v2 (system WebView2 / WKWebView — no bundled browser).
- **Frontend:** SolidJS + TypeScript + Vite + CodeMirror 6.
- **Backend:** Rust + `tokio-postgres` (text/simple protocol), `native-tls`, `keyring`.

## Build / run / verify

```sh
npm install                 # once
npm run tauri dev           # run the app (needs Rust + Node 20)

# Validate after edits (ALWAYS do this before claiming done):
cargo build --manifest-path src-tauri/Cargo.toml      # backend
npm run build                                         # frontend bundle
npx tsc --noEmit -p tsconfig.json                     # frontend types
```

- **After Rust changes → tell the user to restart `npm run tauri dev`.** Frontend-only changes hot-reload.
- Installers are built in CI: push a `v*` tag → `.github/workflows/release.yml` builds mac (universal) + Windows (NSIS, per-user) and drafts a GitHub release. Don't cross-compile locally.

## Conventions

- Update `CHANGELOG.md` (`[Unreleased]`) on every change.
- Run the three validate commands above after edits.
- Surfacing errors: `db.rs`'s `From<tokio_postgres::Error>` unwraps the real Postgres message (don't regress to bare "db error").

## Architecture

### Backend — `src-tauri/src/`
- **`lib.rs`** — Tauri app. `AppState` = connection registry (`HashMap<id, Arc<Mutex<ConnState>>>`). Commands: `connect`, `connect_profile`, `disconnect`, `list_profiles`, `save_profile`, `delete_profile`, `run_query` (+ `run_single_stmt`), `validate_sql` (editor server-lint — PREPARE-only, never executes), `fetch_more`, `list_schema` (now feeds **frontend autocomplete**, decoupled from the lazy tree), `db_tree` (shallow), `table_detail` (per-relation detail on expand), `object_ddl` (Copy DDL), `export_to_file`, `import_rows`. `ConnectResult` carries `read_only` so the UI gates mutating menu items. Plugin init (opener, dialog). `is_cursorable` / `is_read_only_stmt` / `is_prepareable` / `has_bind_params` / `db_error_diag` helpers. **All sidebar mutations reuse `run_query`** — no dedicated DDL-exec commands. `validate_sql` reuses `script::split` + `ensure_alive`, rolls back any open cursor first, runs in autocommit (a failing statement doesn't poison the next), skips DDL/COPY/`$1`-param statements, and maps Postgres' 1-based error position back into the statement. `export_to_file` now takes an `ExportOptions` payload + either an `sql` query (stream, scope=all) or inline `columns`+`rows` (scope=loaded). `read_text_file`/`write_text_file` (tokio::fs) back the editor's Open/Save flow — no `tauri-plugin-fs`. `run_query`/`validate_sql`/`export_to_file` take an optional `search_path` (the console's active schema); `apply_search_path` runs `SET search_path TO <db::ident>, public` (or `RESET`) before exec/PREPARE/DECLARE — threaded into `exec_items` so it survives the reconnect-retry.
- **`db.rs`** — `ConnectionConfig`, `ConnState {client, cursor_open, read_only}`, `AppError` (rich error surfacing). `open()` = connect with TLS (`native-tls`, sslmode) + sets `default_transaction_read_only` when read-only. `collect_rows()` turns `simple_query` messages into `(columns, rows)` where **every value is text or NULL** (no per-type mapping — intentional, handles any type). `ident`/`create_table_text`/`copy_rows` for import.
- **`profiles.rs`** — saved connections. Metadata → `connections.json` in the app config dir; **password → OS keychain** (`keyring`, per-OS features), never plaintext, never sent to the frontend. `upsert`/`delete`/`load_all`/`get_password`.
- **`script.rs`** — SQL **script runner**. `split()` is a byte-level lexer handling `--` / `/* */` comments, `'…'` / `"…"` quotes, **dollar-quotes** (`$tag$`, distinguishes `$1`), and `COPY … FROM stdin` + `\.` data blocks. `run()` executes items in one transaction (rolls back + reports the failing statement); COPY blocks go through `copy_in`. `effective_start()` skips leading comments (so a COPY preceded by a `--` block is still detected).
- **`export.rs`** — **options-driven export**. `ExportOptions` (serde mirror of `src/export.ts`) drives every formatter: delimiter/quote-mode/quoteChar/null-repr/header/line-ending/BOM/column-projection + SQL (table, multi-row INSERT, CREATE) + xlsx (sheet, bold header, autofilter, freeze). `run_export_query` streams a query via a server-side cursor (10k batches, constant memory for text via `TextEmit`, lazy file create → empty result writes nothing); `run_export_rows` formats inline (loaded) rows. **Excel** (`XlsxSink`, `rust_xlsxwriter`) buffers the workbook in memory (NOT constant-memory) and **rolls into a new sheet every 1,048,576 rows**. The TS clipboard path (`formats.ts` `formatWithOptions`) must match these formatters byte-for-byte.
- **`tree.rs`** — introspection. `build_shallow()` = fast connect-time tree (`DbTree { database, databases, schemas[] }`, each schema's tables/views/sequences/functions as **name+kind stubs** + table comment; includes empty schemas). `table_detail(schema, name)` = lazy per-relation columns (with `is_pk`/`is_fk`/nullable/default/**comment**), indexes, constraints — resolves the relation's OID via a **parameterized** query, then drives detail queries by that trusted integer.
- **`ddl.rs`** — `object_ddl(kind, schema, name)` reconstructs runnable `CREATE` DDL from `pg_catalog` (pg_dump-style): tables (identity/generated/serial defaults; PK/unique/check inline; **FKs as trailing ALTERs**; plain indexes only — constraint-backed skipped; table+column comments), views/matviews (`pg_get_viewdef`), functions (`pg_get_functiondef`, overloads; aggregates/window flagged via `prokind`), sequences (`pg_sequences`). User input bound as params, then by OID. Out of scope: partitions, inheritance, RLS, triggers, storage params, tablespaces, collations.
- **`main.rs`** — `tusk_lib::run()`.

### Frontend — `src/`
- **`App.tsx`** — everything UI. Connect screen (saved-profile list + form). Workspace: topbar, **resizable** sidebar (`<Tree>` + **object filter** box), **tabbed editor** + **resizable** editor/results split, virtualized result grid, statusbar with **Export…** configurator + **Import** modal. **Editor tabs** (`src/tabs.ts` `Tab`): each owns a `sql` buffer, `filePath`/`dirty`, and a `ResultSnapshot` (the result grid is per-tab); App-level `columns()/rows()/done()/status()/setStatus/setRunErr` are now accessors over `activeTab().result` (so the grid JSX is unchanged). The **result grid is `ResultGrid.tsx`** (extracted); App owns data/streaming/cursor + the global `ContextMenu`/`cellView` and passes accessors + callbacks (`onSortFilter`→`executeQuery(wrapped,…,"wrapped")`, `onLoadMore`→`loadMore`, `onMenu`→`setMenu`, `onViewValue`→`cellView`). `executeQuery(sql, base, mode)` is the shared runner: `mode:"base"` records `baseQuery` + resets the grid view's sorts/filters (fresh `gridView` if the column set changed), `mode:"wrapped"` keeps it; both bump `result.epoch` (grid resets scroll). `doRun(override?)` runs selection-or-whole; `cursorOwnerTabId` tracks which tab owns the single server cursor and gates `loadMore`; `loadAll` drains it. File flow: `openFileDialog`/`saveActiveTab`/`saveAsActiveTab` (native dialogs + `read_text_file`/`write_text_file`), `openNewTab`/`closeTab` (dirty→confirm), window keydown for ⌘/Ctrl T/W/S/Shift-S/O. A toolbar **active-schema** selector (`schemaNames` memo over `schema()`) sets `activeTab().searchSchema` → passed as `searchPath` to run/validate/export and as `activeSchema` to the editor. Export opens `ExportDialog` over a **frozen `exportSrc` snapshot** (so a tab switch mid-dialog can't redirect it). Owns the sidebar action layer: `menuItems(node)`, `runDDL()`, `copyDDL()`, `editAsSql()`/`scaffoldEditor()`, the `tableDetail` cache + `loadDetail()`, and `activeDialog`/`menu` signals. `schema` (autocomplete list) + `details` come from `list_schema`/`table_detail`, not the tree.
- **`ResultGrid.tsx`** — hand-rolled, two-axis-virtualized read-only grid. Frozen header + row-number gutter are **synchronized transform panes** (header `translateX(-scrollLeft)`, gutter `translateY(-scrollTop)` on the body scroller's `onScroll`), NOT `position:sticky` (reliable in WKWebView). `displayCols`/`offsets`(prefix-sum)/`colAt`(binary search) drive column windowing; rows windowed by `scrollTop`. Per-tab display state is `tabs.ts` `GridView` (widths by *original* index, `order`, `hidden`, `sorts`, `filters`); `props.view()`/`setView`. Selection (cell/range/rows/cols in **display space**), mouse drag + edge auto-scroll, keyboard nav, multi-format copy (reuses `formats.ts`). Server sort/filter re-run via `grid/query.ts` `wrapQuery` (**`src/grid/query.ts`**: `SELECT * FROM (<base>) _tusk [WHERE ILIKE] [ORDER BY ordinal]`).
- **`Tree.tsx`** — recursive explorer. Per-row right-click → `onContext(e, NodeDescriptor)`; click/right-click select (`onSelect` + `selectedKey`/`nodeKey`, drives the context-aware **＋** menu); lazy detail via `onExpandTable`; client-side `filter`. Relation expand keys are kind-prefixed (`tbl:`/`view:`) to avoid table/view collisions.
- **`ContextMenu.tsx`** / **`Dialog.tsx`** / **`WorkbenchDialogs.tsx`** — generic right-click menu; modal shell + `SqlPreview` + `DialogFooter` (live SQL + Cancel/Edit-as-SQL/primary); dispatcher rendering the form for the active `DialogState` (union with per-form payloads + closures).
- **`forms/*`** — one component per action (CreateTable, Column add/edit, **ModifyTable** = DataGrip-style diff editor, Index, Constraint, Schema, Database, Rename, Duplicate, Comment, generic Confirm for drop/truncate). Each owns local state, derives a live `createMemo` SQL preview, and calls back `onRun`/`onEditAsSql`. `ModifyTableForm` diffs an edited column list (+ index/constraint drops + table rename/comment) into the minimal `ALTER` script.
- **`SqlField.tsx`** — single-line CodeMirror with Postgres highlighting + autocomplete (types / functions / passed columns); used for type/default/expression fields in the create & modify dialogs.
- **`sql/ddl.ts`** — pure single-statement SQL builders (the heart of "build SQL in TS"). **`sql/ident.ts`** — `ident`/`qualify`/`lit` quoting, mirrors Rust `db::ident`.
- **`SqlEditor.tsx`** — CodeMirror 6, now a thin **composer** over `src/editor/*` extension factories (using `Compartment`s for live dialect/theme/auto-fold reconfigure — no rebuild, no history reset). Dialect highlighting, **override autocomplete** (context-aware), live keyword auto-capitalization, layered **lint**, folding, search, multi-cursor, statement gutter, **Tab-only accept**. `EditorApi`: `getRunText`/`getCurrentStatement`/`getDoc`/`insertAtCursor`/`format`/`openSearch`/`focus`/… The value effect replaces the whole doc but is **guarded** (`applyingExternal` + `addToHistory.of(false)`), so restores/file-opens don't echo through `onChange` or pollute undo; scaffolding still uses `insertAtCursor`.
- **`editor/`** — the editor's extension modules. `lexer.ts` (**keystone**: TS port of `script.rs` `split`/`dollar_tag_end`, `maskNonCode`, `lexState` shared cache), `autofold.ts` (display-only large-literal folding), `foldBasics.ts` (manual fold gutter + SQL paren fold service), `heuristicLint.ts` + `schemaLint.ts` + `serverLint.ts` + `lint.ts` (two `linter()`s: sync client @300ms, async server @600ms), `format.ts` (`sql-formatter`, dollar-quote carve-out), `search.ts`, `multiselect.ts`, `statements.ts` (run gutter + active-statement + cursor readout; a `runningField`/`setRunningEffect` swaps the running statement's `▶` for a spinner — App passes `running={running() && runningTabId()===activeTabId()}` to `SqlEditor`, which re-applies it via effect after each tab switch since `setState` resets the field), `keywordCase.ts`, `theme.ts`, `distance.ts` (Damerau-Levenshtein), `types.ts` (`EditorPrefs`/`ValidateFn`/…). **`store.ts`** — localStorage `prefsStore` + `tabsStore` (per-connection tab set: buffers/paths, not results). **`tabs.ts`** — `Tab`/`ResultSnapshot`/`makeTab`. **`export.ts`** — `ExportOptions` (+ `formatWithOptions` lives in `formats.ts`, parity with Rust); **`forms/ExportDialog.tsx`** — the configurator.
- **`sql/dialects.ts`** — per-dialect keyword/function/type lists + CodeMirror dialect. Postgres complete; **MySQL/SQLite/MSSQL staged** for future drivers.
- **`sql/aliases.ts`** — shared schema-index + alias resolution (`aliasMap`/`tableByRef`/`currentStatement`/`makeIndexer`/`Col`/`Table`), used by **both** `completion.ts` and `editor/schemaLint.ts` so they never diverge.
- **`sql/completion.ts`** — the context-aware completion source: clause detection (tables after FROM/JOIN, columns after SELECT/WHERE/…), alias resolution (`u.` → that table's columns), schema qualification, ranked in-scope cols > tables > functions > keywords. `$` deliberately excluded from completion tokens. (Index/alias helpers now live in `sql/aliases.ts`.)
- **`formats.ts`** — CSV/JSON parsing for **import** (export formatting now lives in Rust/`export.rs`).

## Gotchas (read before debugging)

- **Values are text.** `simple_query` returns everything as strings; `NULL` = `None`/`null`. Don't assume typed values.
- **Single statement vs script.** A single read statement streams to the grid via a server-side cursor; multiple statements or a COPY block run as a transactional script (summary, no grid). Routing is in `run_query` via `script::split`.
- **COPY detection ignores leading comments** (`effective_start`). pg_dump prefixes every COPY with a `--` block; missing this sends COPY to `batch_execute` → `CopyInResponse` → "unexpected message from server".
- **Keychain in dev:** unsigned `tauri dev` builds re-prompt / invalidate saved passwords across rebuilds (macOS ties items to the code signature). Seamless in signed release builds. `keyring` features are per-OS in `Cargo.toml`.
- **TLS:** `native-tls` (SecureTransport on mac, SChannel on Windows; needs OpenSSL on Linux). `sslmode`: `disable` | `prefer` (default) | `require` (encrypt, no cert verify) | `verify-full` (verify).
- **Read-only mode:** server `SET default_transaction_read_only = on` **and** a client-side write/DDL guard. The sidebar additionally disables mutating menu items (defense-in-depth) via `ConnectResult.read_only`.
- **Dropped connections auto-recover; query duration is never capped.** `ConnState` keeps the `ConnectionConfig` (incl. password — server-side only, never sent to the frontend); every query command calls `ensure_alive` (re-opens when `client.is_closed()`), and `run_query` retries once if a query dies mid-flight. So idle-timeout / server-restart heals on the next action. `db::open` sets a **10s `connect_timeout`** + **aggressive TCP keepalives** (`keepalives_idle` 5s, `keepalives_interval` 2s, `keepalives_retries` 3, `tcp_user_timeout` 15s) so a genuinely dead connection surfaces as `is_closed` in ~10-15s and the in-flight query errors — but a slow live query keeps getting ACKs and runs unbounded (no `tokio::time::timeout`). A re-open drops any open streaming cursor (`cursor_open` reset) — so `fetch_more` checks `was_streaming && !cursor_open` after `ensure_alive` and returns an **error** ("connection dropped mid-stream — … Re-run the query …") rather than a silent `done:true` that would present a truncated result as complete. The frontend `loadMore` catch surfaces any fetch error in the result error banner (over the rows fetched so far) + a `streaming stopped — …` status, then stops paging (don't regress either back to console-only/silent-done). The Run button shows a live elapsed counter (`runMs` + `fmtDur`).
- **Autocomplete corrupting dollar-quotes** was caused by Enter-accept + `$` tokens — fixed; keep accept Tab-only and `$` out of completion tokens.
- **Lazy tree ⇒ autocomplete uses `list_schema`, not the tree.** The shallow `db_tree` no longer carries columns, so autocomplete is fed by `list_schema` (one query). Expanding a node fetches `table_detail` (cached); after DDL, `runDDL`→`loadSchema` refetches the shallow tree + `list_schema` and re-fetches already-open details.
- **Sidebar DDL must stay single-statement where it matters.** `CREATE/DROP DATABASE` can't run in a transaction — keep them one statement (multi-statement input routes to `script::run`, which wraps in `BEGIN`). Builders in `sql/ddl.ts` emit one statement each (comma-separated ALTER actions, not `;`-joined); multi-statement cases (duplicate-with-data, column edit + rename) are intentionally table-only.
- **Copy DDL is reconstructed, not pg_dump.** Driven by OID; constraint-backed indexes are skipped and FKs deferred to trailing ALTERs so replay doesn't error. Partitions/inheritance/RLS/triggers/storage are out of scope (see `ddl.rs`).
- **Quoting parity.** `sql/ident.ts` must match Rust `db::ident` exactly (double `"`; literals double `'`). Always quote identifiers in generated SQL.
- **Never `::text`-cast a boolean in catalog queries.** `collect_rows` reads the text protocol: a *bare* bool comes back `"t"`/`"f"`, but `bool::text` (e.g. `i.indisunique::text`, `(con.oid IS NOT NULL)::text`) comes back `"true"`/`"false"`. The code compares against `"t"`, so a cast silently makes every check false. Select the bare bool (`i.indisunique`, `(NOT a.attnotnull)`). Char columns (`relkind`, `attidentity`, `contype`) DO need `::text`.
- **`editor/lexer.ts` must mirror `script.rs`.** Auto-fold, both client lints, and the formatter's dollar-quote carve-out all classify spans via this lexer — it must match `split`/`dollar_tag_end` byte-for-byte (incl. `$1` = param, not a tag). It's UI-only: it skips psql `\meta` + COPY-data handling that `script::split` does, so server-lint statement *indices* can diverge from the TS `splitStatements` on a script containing a `COPY … FROM stdin` block (rare; typed queries align).
- **Auto-fold is display-only.** It replaces ranges with widget decorations; the document text is never modified, so `getRunText`/`getDoc`/export always return the full expanded query. Folds recompute on doc-change (candidate geometry) and on every selection move (cursor in a range → expanded). Don't reach for `@codemirror/language` fold state for this — that's the separate *manual* fold gutter (`foldBasics.ts`).
- **One cursor, many tabs.** There's a single server-side cursor per connection (`tusk_cur`), so only one tab can stream at a time. `doRun` frees another tab's cursor and marks its snapshot `done` before running; `cursorOwnerTabId` gates `loadMore` so scrolling a non-owning tab never `FETCH`es the wrong cursor. Any sidebar command also rolls the cursor back — the owner tab's stream just stops (snapshot frozen). Per-tab editor state (undo/cursor/fold) lives in a `Map<tabId,EditorState>` in `SqlEditor.tsx`; **`view.setState()` replaces all state incl. compartments**, so every tab state is built via the shared `buildExtensions` (seeded with the current dialect/theme/fold), and the guarded value-effect skips during a swap (`props.tabId === curTabId`) so it can't clobber the outgoing tab.
- **Grid `<For>` bodies must read via accessors, not `const`.** In `ResultGrid.tsx` the windows iterate index ranges (`range(visCols…)`); inside, use `const oi = () => displayCols()[k]` / `const val = () => rows()[r]?.[oi()]` (functions), NOT `const oi = displayCols()[k]`. A plain const is captured once at item-render; since the `For` key (the index) doesn't change on a sort re-run (rows replaced) or reorder (displayCols changed) with the same window, captured consts go stale and cells show old data / the sort glyph never appears. Read reactively in the JSX. The grid's frozen header/gutter are transform panes (not sticky); a new query bumps `result.epoch` so the grid resets scroll (vs a tab switch, which restores it) — keyed on `${tabId}:${epoch}`. **That key MUST be a `createMemo`, not a plain `() =>` function.** `on()` re-runs its callback whenever a tracked dep *notifies*, not only on value change, and `epoch` reads through App's `activeTab()` memo whose identity changes on every `patchTab`/`patchResult` — so a plain key fired the reset (scrollTop→0 + selection clear) on every row append / resize / reorder / hide, making those feel broken. The memo dedupes by string so the reset runs only on a real tab switch or epoch bump. **Scroll never writes to reactive state**: `onScroll` updates only the local `scrollTop`/`scrollLeft` signals (only the window memos depend on them) + a non-reactive per-tab `scrollMem` Map. Persisting scroll into `gridView`/`setView` per frame rebuilds the tabs array and cascades a full-App recompute every frame — it froze/crashed large tables. Keep scroll out of `view`.
- **Active schema is per-tab, applied per run.** `Tab.searchSchema` (null = default) drives `SET search_path` on the *shared* session — so it must be re-applied (or `RESET`) on every run_query/validate/export, never assumed sticky. Autocomplete labels a table bare when its schema is `public` or the active schema (`makeSqlCompletion`'s 3rd `getActiveSchema` arg). Export scope=all uses the *producing* tab's schema via the `exportSrc` snapshot. Schema-lint still resolves bare names via `byBare` (no active-schema preference yet — minor, deferred). **Generated query scaffolds** (`genSelect`/`genInsert`/`genUpdate`, `runTable`) use `qualifyIn(schema, name, activeSchema)` — drops the schema prefix when it matches the tab's active schema — and open a **new tab** via `openGeneratedTab` (schema set to the relation's) rather than clobbering the active tab. DDL builders keep using `qualify` (always explicit — never depend on search_path for drop/alter/rename).
- **Lint squiggles: SVG background, not `text-decoration: wavy`.** WKWebView (the macOS Tauri runtime) renders `text-decoration-style: wavy` unreliably. `.cm-lintRange-{error,warning,info}` in `App.css` use a repeating inline-SVG wavy underline (CodeMirror's own mechanism), recolored. Don't set `background: none` on those (it removes the squiggle), and don't rely on `wavy` text-decoration. Lint diagnostics are generated by the client (heuristic+schema) + server linters regardless — this is purely the *painting*.
- **Export parity + scope.** `export_to_file` streams a query (scope=all) or formats inline rows (scope=loaded); the clipboard path uses TS `formatWithOptions` which must stay byte-identical to `export.rs` (delimiter/quote/null/header/column-projection/line-ending) — same parity class as `ident.ts`↔`db::ident`. The Export dialog reads a **frozen `exportSrc` snapshot**, not live `columns()/lastQuery()`. xlsx is file-only (no clipboard) and buffers the whole workbook (rolls into new sheets past 1,048,576 rows).
- **`validate_sql` never executes.** It only `PREPARE`s (parse+plan) then `DEALLOCATE`s, in autocommit, after rolling back any streaming cursor. It skips DDL/COPY and `$1`-param statements (PREPARE can't infer their types). The frontend skips it while `running()` (shared connection lock) and when the `serverLint` pref is off. Position math: PG's 1-based offset is into `PREPARE … AS {stmt}` → backend subtracts the prefix (chars), frontend adds the statement's leading-whitespace offset.
