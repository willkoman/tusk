# Changelog

All notable changes to **Tusk** (fast native Postgres-first DB client). Format loosely follows Keep a Changelog. Newest first.

## [Unreleased]

### Changed
- **Tab strip scrolls with the mouse wheel** when it overflows (vertical wheel → horizontal scroll).
- **Running-query spinner: pinned + visible on the tab.** The statement-gutter spinner used to follow the cursor's statement, so clicking around while a query ran dragged the spinner to blocks that weren't doing anything — it's now pinned to the statement where the run actually started (anchor mapped through edits). The tab strip also shows a small spinner on whichever tab owns the in-flight query, so a run stays visible from any tab.
- **Completion knows the live function/procedure catalog.** After `CALL` / `EXEC` / `EXECUTE` / `PERFORM`, the database's own callables (the `list_functions` catalog that already feeds the lint) top the suggestion list; they're also offered in general expression contexts alongside the dialect builtins (they were absent from completion entirely).
- **Explorer: double-click runs the table reliably.** The second click of a double-click no longer re-collapses the node the first click expanded, and scroll anchoring is disabled on the tree so expanding a node at the scrolled-to-bottom edge can't shift the clicked row out from under the cursor (which made double-click physically impossible there).
- **AI schema context: relevance-ranked, never silently truncated.** The system prompt's schema dump (was: first ~8KB of the table catalog in list order, rest dropped) now ranks tables by relevance first — any table mentioned in the conversation, the editor SQL, or sharing a name token with them gets its full column list ahead of the budget (raised to ~12KB) — and every table past the budget is still listed by name so the model knows it exists and can ask. Fixes "table X wasn't in the truncated schema list" on large schemas.
- **AI composer is a multiline textarea**: grows with content up to ~5 lines (then scrolls), Enter sends, Shift+Enter inserts a newline.

## [0.4.8] - 2026-06-11

### Changed
- **Workspace toolbars reorganized + responsive.** The editor toolbar (Run / file ops / Format / Find / Explain / schema / font / wrap) now sits **above the editor** under the tab strip, and a new **result toolbar above the output** carries everything result-specific: the Plan/Grid toggle (no longer floating over the grid), Load all + streaming state, the pending-edit controls (✎ count / Commit… / Discard / + Row), "Copy w/ column names", Export…, and the elapsed-time readout. The footer status bar slims down to the status message + cursor position. The editor toolbar is responsive via container queries on the editor pane (so sidebar resizing counts): the shortcut hint drops first, then the text actions collapse into a ⋯ overflow menu (same actions, plus Explain), then the font/wrap icons hide — nothing clips, and every collapsed action stays reachable.
- **AI chat streams smoothly and stops yanking the scroll.** Each streamed delta replaced the last message object, and the list was keyed on object identity — so the entire assistant bubble's DOM was torn down and rebuilt on every chunk (choppy rendering), and an unconditional scroll-to-bottom ran per delta (reading scrolled-up text was impossible while streaming). The message list now keys by position (the streaming bubble's DOM is patched, not rebuilt), and auto-scroll only engages while you're actually at the bottom — scrolling up releases the pin, scrolling back down (or sending a new message) re-engages it.
- **Theme contrast pass.** Light theme: TRUE pills, new-row markers, dirty-cell amber, the pending-edit counter, the row-count chip on selected tree rows, and the new-column highlight in Modify table were all dark-surface tints that washed out on white — re-pinned to saturated light-palette equivalents. Both themes: deleted-row gutter numbers, the updater error line, and the AI "key saved" check now ride the semantic `--danger`/`--ok` variables instead of hardcoded dark-theme colors.

## [0.4.7] - 2026-06-11

### Changed
- **Modify-table dialog is wide.** The per-row column editor (name / type / null / PK / default / comment) was squeezed into a 680px modal (~110px per field); the dialog now sizes to the viewport (up to 1100px), the column list scrolls at up to ~48vh instead of a fixed 320px, and the grid gives default/type/comment the extra room.
- **Neighborhood graph: readable edge labels + draggable cards.** The column gap is now sized to the longest `src → dst` edge label (was a fixed 330px column pitch that left only 80–130px of air, running labels underneath the cards), and every card — neighbors and the center table — can be click-dragged to reposition (5px tolerance keeps plain click = re-center), with edges following live and a Reset layout button for the neighborhood scope too. Repositioning clears on re-center.
- **Copying boolean cells yields the displayed word.** Grid copy (selection TSV/CSV/JSON/Markdown, Copy column, Copy cell value) now maps boolean-detected columns to the same TRUE/FALSE words the pills display, instead of the driver's raw token (`t`/`f` on Postgres, `0`/`1` on SQLite). "View value…" still shows the raw underlying token, and file export streams raw values as before.

## [0.4.6] - 2026-06-11

### Changed
- **Schema ERD layout overhauled: proximity packing instead of left-to-right layers.** The whole-schema diagram no longer ranks tables into FK-depth columns (which made even modest schemas grow into wide ribbons needing constant panning). Family clusters are now placed by a greedy adjacency packer: the most-connected cluster seeds the canvas and every subsequent cluster lands on the nearest free spot to the weighted centroid of its already-placed referrers — spiral candidate search with distances normalized by average card dimensions (so the X and Y axes are spent in proportion to what a card costs on each), a gentle centroid pull that curls chains into the blob instead of letting them ribbon off, and refinement sweeps that relocate any table with a strictly shorter free spot near its full neighborhood. Tables sit as close to their referrers as the no-overlap rule allows; zero overlap and bit-exact determinism hold by construction (no RNG, no convergence loops). Naming-family containers, the bottom island grid, and component shelf-packing are unchanged; family *internals* keep the small layered mini-flow. On the test fixtures: an 8-table chain drops from 26.8:1 to ~3:1 aspect, a 12-table shop schema's mean FK edge shortens ~35%, and a 19-table multi-family schema goes from a 3.8:1 strip to ~1.2:1 at 35% shorter edges.
- **ERD edges between vertically stacked cards route as a right-side loop** instead of degenerating into a near-vertical squiggle through the cards (stacking is common now that the layout uses both axes).

## [0.4.0] - 2026-06-10

### Fixed (correctness sweep)
- **Multi-statement scripts are now atomic on every driver.** DuckDB/SQLite ran scripts as a bare batch and MySQL as a plain loop — a mid-script failure left earlier statements applied, despite the rollback promise. Scripts now run inside BEGIN…COMMIT (best-effort ROLLBACK on error) on DuckDB/SQLite and START TRANSACTION…COMMIT on MySQL (whose DDL still auto-commits — engine behavior). Scripts that manage their own transaction (BEGIN/COMMIT/SAVEPOINT anywhere) run unwrapped. Conformance: a failing 3-statement DML script leaves zero changes on all four engines.
- **Grid filters work on MySQL/SQLite.** The sort/filter wrap hardcoded Postgres-only `ILIKE`; it now emits per-dialect expressions (`CAST … AS CHAR/TEXT LIKE` on MySQL/SQLite). Sort/filter is also disabled on MySQL results with duplicate column names (the derived-table wrap errors 1060).
- **Sidebar DDL is gated to Postgres.** The form dialogs emit PG-syntax DDL; on MySQL/SQLite/DuckDB every mutating menu item is now disabled with an explanatory tooltip instead of failing at apply time.
- **DDL exec messages say "OK"**, not "(0 rows affected)" — which read like failure. Also fixes SQLite reporting the *previous* statement's change count after DDL, and DuckDB misclassifying standalone DDL as an empty result grid (its synthetic "Count" column).
- **Multi-statement runs say what happened to earlier statements** — the status now appends "earlier statements executed — only the last result is shown" (or a count) instead of silently dropping prior results.

### Added
- **In-grid data editing.** Results from a single-table SELECT (with the table's full primary key in the result) become editable on every driver: double-click a cell to edit inline (Enter commits + moves down, Tab right, Esc cancels, Alt+N sets NULL; Ctrl/Cmd+double-click keeps the value viewer), mark rows for deletion (Delete with rows selected, or the context menu), and add new rows (**+ Row** in the statusbar — untouched cells take the column default). Nothing touches the database until **Commit…**: a dialog previews the exact UPDATE/DELETE/INSERT script (WHERE clauses built from the rows' *original* primary-key values — composite PKs AND-ed, NULLs via IS NULL), which runs as one transaction (rolled back wholesale on failure, pending edits kept). Pending changes overlay the grid (amber = edited cell, red strikethrough = delete, green = new row) with a statusbar counter + Discard; re-running/sorting/filtering with uncommitted edits asks first. Non-editable results explain why in the cell context menu (joins, no PK, read-only connection, …). DuckDB table details now report primary keys (pragma_table_info) so its grids are editable too. Limitation: no optimistic-concurrency check yet — last write wins. Pure SQL-builder + editability cores are vitest-covered. **Safety hardening:** editing is offered only for *plain column* select lists — any expression, function, CASE, literal, or alias in the SELECT (e.g. `id*2 AS id`) disables editing, because a value colliding with a column name would make the commit's PK WHERE clause target the wrong row; WITH/TABLE/VALUES forms are likewise read-only. Cells from columns not belonging to the table can't be edited; a column-selection never expands into row deletes; Postgres roles without any write privilege on the table get a read-only grid with the reason; grid copy reads the displayed (pending) values.
- **Parameter prompts.** Running SQL containing `$1`-style positional or `:name` parameters (outside strings/comments/dollar-quotes) opens a prompt dialog — per-param value, NULL toggle, or raw mode (verbatim splice for numbers/expressions) — with a live preview of the substituted SQL; values are remembered per tab. Server-side lint skips `:name` statements like it already did `$1` (PREPARE can't infer their types). Known limitation: PG array slices with identifier bounds (`arr[i:j]`) can false-positive `:j` — use raw mode.
- **FK-aware JOIN completion.** After `JOIN orders o ON `, completion proposes complete join conditions (`o.user_id = u.id`, multi-column FKs AND-joined) for every foreign key linking the just-joined table to any other table in the statement, fed by the live FK catalog (active schema + public, fetched lazily per schema). Pure hint core is vitest-covered.
- **Tree metadata: row estimates, sizes, triggers.** Postgres tables/matviews show `≈rows · size` in the explorer (planner `reltuples` + `pg_total_relation_size`; never-analyzed tables show nothing), and expanded tables list their user triggers (`pg_get_triggerdef`, internal FK triggers hidden) with Copy DDL / open-in-editor / Drop… context actions.
- **Export works on every driver.** Scope=all streams via LIMIT/OFFSET pages through the same formatters on DuckDB/SQLite/MySQL (PG keeps its snapshot-consistent server cursor). Caveat: paged export isn't snapshot-consistent under concurrent writes on MySQL. Conformance: 25k-row CSV crossing the page boundary, all engines.
- **Profiles for every driver.** Saved connections now carry `driver` + `path` — DuckDB/SQLite profiles (file path or :memory:) and MySQL profiles with saved passwords all round-trip; the profile list shows each driver's mascot and a path/host sublabel; old `connections.json` files load unchanged. "Connect on startup" available for all drivers.
- **Tab QoL:** right-click a tab → Rename… / Close / Close others / Close tabs to the right (dirty tabs are kept and reported); drag tabs to reorder (order persists per connection).
- Dev builds use `line-tables-only` debuginfo (the bundled DuckDB/Arrow tree generated ~20 GB of target artifacts and kept filling the disk).

## [0.3.0] - 2026-06-10

### Added
- **Rich EXPLAIN plan visualization.** Any result detected as EXPLAIN output gets a Plan/Grid toggle in the result area: a pan/zoomable plan tree (hand-rolled tidy layout + SVG edges, HTML node cards) with per-node cost/rows/time, heat coloring (by cost, actual time, or rows — configurable, sqrt-scaled, theme-aware), collapsible subtrees, and a docked details panel with every raw property. Per-engine parsing, best-effort: Postgres `FORMAT JSON` (full, incl. ANALYZE actuals + exclusive-time math) and hand-typed text EXPLAIN (strict indentation parser); MySQL `FORMAT=JSON`; SQLite `EXPLAIN QUERY PLAN` (parent-id tree; bytecode `EXPLAIN` stays in the grid); DuckDB JSON when the build supports it. Anything unparseable falls back to a styled monospace text view — never a broken tree, and the raw grid is always one toggle away. New **Explain ▾** toolbar action (+ palette entries) wraps the current statement/selection in the engine's best structured EXPLAIN; **Explain Analyze** warns before executing a mutating statement (and is disabled on SQLite). Settings → Plans: orientation (top-down / left-to-right), heat metric, node density. Parsers and layout are pure TS with a vitest suite.
- **Schema diagram from the explorer.** Right-clicking a schema node opens the relationship viewer straight into the whole-schema ERD (DDL pane fills in once you click a table card; Neighborhood unlocks the same way).
- **ERD manual repositioning.** Click a table card still opens its neighborhood + DDL; click-**drag** moves the card (edges follow live, position pinned until moved again or the graph reloads). Dragging a family container's label strip moves the whole block with all member tables. Drag deltas are zoom-aware (screen ÷ scale) with a 5px click tolerance so clicks and drags never misfire. A **Reset layout** button (whole-schema header, enabled once anything was moved) discards all manual pins back to the computed layout. Tables with no relationships always live in the disconnected block — never inside a family container.
- **ERD packs as a grid/matrix.** Component blocks shelf-pack in two dimensions toward a ~3:2 overall aspect (no more single endless ribbon); the sub-column height budget adapts to content area so every family block and component shapes itself square-ish; each sub-column is only as wide as its own widest member (a big family block no longer inflates neighboring columns); islands form a dense width-bounded grid at the bottom behind a gutter; cards enlarged (240px, bigger type) so one fit-view is readable without zoom-pan-zoom loops.
- **ERD is horizontal-focused, cluster-first, and family-grouped.** Naming families (`product_*`, `product_content_*`, `purchase_order_*` — longest 1- or 2-token underscore prefix shared by ≥2 tables) are laid out as **compound blocks**: members arranged inside a labeled dashed container, then the cluster graph (families as super-nodes, FK edges aggregated) goes through the same distance-minimizing layered engine — so blocks sit adjacent to what they reference and intra-family edges collapse to near-zero length (organization AND short relationship chains). FK-less tables whose family lives in the web are adopted into their family block; true islands form a compact block at the FAR LEFT behind a wide gutter. Connected components pack side-by-side (diagram height = tallest cluster), over-tall layers wrap into sub-columns, gaps tightened. The DDL pane auto-collapses to a thin rail in whole-schema scope (auto-expands in Neighborhood; toggle anytime).
- **ERD readability overhaul** (real-schema feedback): layout now separates weakly-connected components into their own bands, FK-less tables form a compact grid block instead of bloating the first column, never-referenced tables are pulled adjacent to their FK targets (dissolves the "everything stacked on the left" mega-column longest-path layering produces on hub-and-spoke schemas), and a neighbor-median pass aligns children vertically near their parents. Edges are **colored by the table they point at** (deterministic hue, matching chip on each card header), edges sharing an anchor fan out a few px so lines never coincide, audit-style mega-hubs (a table targeted by ≥35% of all FKs, e.g. `created_by → users`) render faint until hovered, and hovering any card lights up only its edges while everything else dims. Initial fit no longer races the async load (blank-until-pan bug).
- **"DDL & relationships…" explorer action.** Right-click a table/view → a large viewer: left pane shows the reconstructed CREATE DDL (syntax-highlighted, Copy / Open in editor); right pane shows the FK graph in two scopes — **Neighborhood** (inbound referencing tables ← center table with full column list → outbound FK targets, column-level edge labels, click any neighbor to re-center) and **Whole schema** (ERD of every table with PK/FK columns, deterministic layered layout with cycle-breaking + barycenter ordering, hover-highlighted edges, click a card to drill into its neighborhood). New backend commands `table_relationships`/`schema_relationships` introspect FKs structurally on all four engines (PG pg_constraint w/ ordered column lists, MySQL KEY_COLUMN_USAGE, SQLite pragma_foreign_key_list incl. implicit-PK references and inbound scans, DuckDB duckdb_constraints best-effort — empty, never an error); covered by new driver-conformance tests (single + composite FKs, inbound/outbound, ERD flags, DDL roundtrip).
- **Copy DDL works on every driver.** `object_ddl` now dispatches per engine — PG keeps the full pg_catalog reconstruction; SQLite returns `sqlite_master` DDL (+ index DDL); MySQL uses `SHOW CREATE TABLE/VIEW`; DuckDB reads `duckdb_tables()`/`duckdb_views()` where available. Previously PG-only.
- **vitest test suite** (`npm test`): plan parsers, EXPLAIN wrapping, tidy-tree layout, ERD layered layout — pure-TS units, node environment.
- **Settings dialog.** A gear button in the topbar opens a tabbed Settings modal (Editor / Appearance / Grid / Shortcuts) consolidating every preference; changes apply live (same persisted `tusk.prefs` store as the toolbar quick-toggles, which remain).
- **Light theme + follow-system.** New Appearance → Theme pref: Dark (One Dark), Light, or Follow system. Flips the whole UI palette (CSS variables via `<html data-theme>`), the editor (hand-rolled One Light-ish CodeMirror theme — no new dependency), lint squiggle/AI-code-block colors, and responds live to OS scheme changes.
- **Font & accent customization.** Editor/grid monospace font pref (preset list or any installed family; one `--mono` CSS variable + the editor theme) and an accent color picker (presets + free pick) driving every accent tint via `--accent`/`--accent-rgb`.
- **Grid appearance prefs.** Row density (normal 28px / compact 22px), zebra striping, NULL cell rendering (NULL / empty / —), and default column width — all live, virtualization-safe (row math reads the pref reactively).

- **Rebindable keyboard shortcuts + cheat-sheet.** Every app action (run, run statement, format, tabs, save/open, panels…) lives in a single actions registry (`src/actions.ts`); Settings → Shortcuts lists them grouped and searchable — click a binding, press the new chord (Esc cancels, Backspace unbinds), conflicts warn and replace on confirm, per-row and reset-all restore defaults. Overrides persist (`tusk.keys`, only diffs from defaults) and apply live (window handler + a CodeMirror keymap compartment — no editor rebuild). CodeMirror built-ins (find, fold, undo, completion) are listed read-only.
- **Query history.** Every user-issued run (not grid sort/filter re-runs) is recorded per connection — SQL, status (ok/error/cancelled), duration, row count, active schema — to a JSON file under the app config dir (new `load_history`/`save_history` commands; survives WebView storage resets; storage failures degrade to in-memory and never block a query). A topbar 🕘 panel (or Mod+Shift+H) lists newest-first with search, expandable highlighted SQL, and Insert / Open in tab / Re-run; capped at 500 entries, consecutive duplicate runs collapse.
- **Command palette (Mod+K).** Fuzzy-searchable list of every available action (disabled ones hidden, e.g. query actions while disconnected), showing each action's current shortcut; ↑/↓/Enter to run, Esc closes.

### Changed
- **Scrollbars are themed app-wide.** All scrollbars (tab strip, sidebar, editor, result grid) now use theme-variable thumb colors with transparent tracks in both themes, replacing the default WebView chrome (only the sidebar was styled before). The tab-strip scrollbar is slimmer (5px).

### Added (lint)
- **Production-grade schema lint: unknown columns, functions, procedures, and mid-statement keywords now get squiggles.** Four layers, all with did-you-mean quick-fixes: unknown qualified columns (`u.emial`) and unknown tables (existing); **unknown bare columns** (`SELECT emial FROM users`) checked against the union of in-scope table columns — heavily gated to kill false positives (DML statements only, every table ref must resolve, statements with CTEs or derived tables are skipped since their column sets are opaque); **unknown function/procedure calls** checked against the engine's REAL catalog via the new `list_functions` command (PG `pg_proc` incl. procs, DuckDB `duckdb_functions()`, SQLite `pragma_function_list`; MySQL has no builtin catalog → lint stays off there rather than false-positive); **misspelled clause keywords** (`SELECT id FORM users`) flagged when one edit away from a clause keyword. Grammar vocabulary (EXTRACT fields, frame words, INTERVAL units, cast targets, window names…) is allowlisted via a cross-dialect `ALL_SQL_WORDS` union; `EXTRACT(YEAR FROM x)`-style grammatical FROMs no longer read as table refs (latent bug). The lint core is pure and unit-tested (17 cases, majority false-positive guards). Server lint (PREPARE) remains ground truth when connected.

- **Lint quick-fixes by keyboard + smarter suggestions.** With the caret on a squiggle, **Tab** applies the suggested fix (completion-accept still wins when the popup is open; indent still works otherwise) — also Alt+Enter and Ctrl/Cmd+. — no more chasing the hover tooltip; the tooltip itself gained an invisible hover bridge so the mouse can reach its button without it vanishing. Suggestions now understand **prefix matches**: typing `master` on a table whose column is `master_id` suggests `master_id` (raw edit distance priced every missing character and stayed silent).

### Fixed
- **AI panel opens into chat once set up.** The panel auto-opened its settings section on every open — the "no key saved" check ran before the async keychain lookup resolved, so it always saw zero keys. Routing now happens once the check completes: no saved key → the setup form (provider/model/key prompt) as before; a key exists → straight into the chat.
- **Invalid leading keywords now get error squiggles.** `SELCT * FROM x` previously produced no diagnostic at all: the server linter's `validate_sql` only PREPAREd statements starting with a known-prepareable keyword (so a misspelled first word was silently skipped), and no client linter checked keywords. Three-part fix: (1) the heuristic linter now flags a statement whose first word isn't a statement starter in **any** supported engine (`STATEMENT_STARTERS` union in `sql/dialects.ts`), with a did-you-mean suggestion (Damerau-Levenshtein) — instant and offline; a half-typed keyword under the cursor isn't flagged. (2) `validate_sql`'s allow-list flipped to a skip-list of statements PREPARE legitimately rejects (DDL/utility/transaction control), so anything unrecognized gets a real parser diagnostic with a position. (3) A position-less server error now squiggles the statement's first token instead of collapsing to an invisible range on leading whitespace.

## [0.2.5] - 2026-06-05

### Added
- **Run chooser — whole file vs. current block.** Hitting Run (the button or ⌘/Ctrl+Enter) with the cursor inside one of several statements (and nothing selected) now opens a small popover to choose **Current block** or **Entire file** — pick with a click, or ↑/↓ + Enter (Esc cancels). Backend: `db::collect_rows` reads the simple-protocol `RowDescription`, so a zero-row Postgres result still reports its column names. (`RETURNING` queries that affect no rows likewise show their headers.)

## [0.2.4] - 2026-06-04

### Changed
- **CI release builds are much faster (cache reuse + parallel macOS arches).** Releases were doing a full **cold** Rust compile every time — the `swatinem/rust-cache` restore was a 1-second miss on every run because the workflow only triggered on `v*` tags, and GitHub Actions caches are ref-scoped (a tag run can only restore caches from its own ref or the **default branch**, which never had one). The workflow now also builds on **master pushes / PRs** (compile + type-check only — no bundling), which warms a **per-target** Rust cache (stable `shared-key`) on the default branch that tag releases restore, so a release no longer recompiles the bundled DuckDB/SQLite C++ and the whole dependency tree from scratch. The macOS **universal** job (which compiled aarch64 **and** x86_64 serially) is split into **two parallel single-arch jobs**, so the mac build's wall-clock is ~one arch instead of two — now shipping separate `aarch64` and `x64` DMGs instead of one universal DMG. A `concurrency` group also cancels superseded master/PR runs (never a release tag). No app-behavior changes.

## [0.2.3] - 2026-06-04

### Changed
- **Autocomplete now accepts on Enter as well as Tab.** Pressing Enter with the completion popup open accepts the highlighted suggestion (same `acceptCompletion` as Tab); when no popup is open Enter still inserts a newline normally. This is safe because `$` remains excluded from completion tokens, so the old Enter-accept dollar-quote corruption (which came from `$tag$` delimiters being offered as completions) can't recur.

## [0.2.2] - 2026-06-04

### Changed
- **xlsx export no longer buffers the whole workbook in RAM.** Previously the Excel formatter held the entire workbook in memory until save, so a large export spiked memory (e.g. ~300k rows × 9 cols briefly used ~700 MB). It now uses `rust_xlsxwriter`'s **constant-memory mode** (`add_worksheet_with_constant_memory`, behind the `constant_memory` feature), which streams each worksheet's rows to a per-sheet tempfile — RAM stays flat regardless of row count, matching the text/CSV export path. The streaming export already writes rows strictly top-to-bottom (the mode's requirement); the bold header (row 0) and freeze-panes are unaffected, and the autofilter is now **sealed per-sheet while that sheet is still current** (so constant-memory never has to reach back into a sheet whose rows were already flushed). Sheet rollover every 1,048,576 rows still works. The destination `.xlsx` is still only created at save, so cancel/error leaves no partial file.

### Fixed
- **Double-clicking a table (or any streamed result) capped at 1000 rows.** The editor's server-lint (`validate_sql`) rolls back any open cursor so it can `PREPARE` in autocommit — but double-clicking a table sets the editor document, which fires that lint ~600ms later and **silently rolled back the streaming cursor the query had just opened**. After that, scrolling / "Load all" found no cursor and reported `done`, so the result was stuck at the first page. The frontend now **skips server-lint whenever a streaming cursor is open** (in addition to skipping while a query is running) so editing or generating SQL can't truncate a live stream; lint resumes once the stream finishes or is drained. (Client-side heuristic/schema lints are unaffected.)

### Fixed
- **Network failures fail fast; query duration is never capped.** A query on a dead connection used to spin on "Running…" indefinitely (TCP retransmit can take many minutes). Now a 10s **connect timeout** bounds the open/reconnect path and **aggressive TCP keepalives** (5s idle, 2s interval, 3 retries, 15s `tcp_user_timeout`) drop a genuinely dead connection in ~10-15s → the in-flight query errors and the next action auto-reconnects. A slow-but-alive query keeps getting keepalive ACKs and runs **as long as it needs** (no artificial timeout). The Run button shows a **live H:M:S counter** while a query runs.
- **Dropped connections now auto-recover.** When a Postgres connection was closed underneath the app (idle timeout, server restart, network blip), every subsequent action failed permanently with no way out but disconnect + reconnect. The backend now retains each connection's config (server-side only, never sent to the frontend) and **transparently re-opens** a closed connection on the next action (`ensure_alive`, gated on `Client::is_closed()`); `run_query` additionally reconnects + retries once if a query dies mid-flight. Verified end-to-end (terminate the backend server-side → `is_closed()` flips → next query reconnects and succeeds).
- **Native WebView right-click menu showed instead of the app menu** — the OS/WebView context menu is now suppressed app-wide (`document` `contextmenu` `preventDefault`), so right-click consistently opens the sidebar's own action menu (and nothing in the editor/grid).
- **Sidebar boolean flags were always false** — catalog queries cast booleans to `::text` (e.g. `(NOT a.attnotnull)::text`) and compared against `"t"`, but `bool::text` yields `"true"`/`"false"` (only a *bare* bool renders `"t"`/`"f"` over the text protocol). So every column showed as `NOT NULL`, and index `unique`/`primary` flags were wrong. Found via GUI test against a real DB. Fixed by dropping the `::text` casts (tree.rs `table_detail`, ddl.rs `object_ddl`). This also fixed Copy DDL emitting constraint-backed PK/unique indexes (the `backs` dedup flag was stuck false → duplicate-index errors on replay) and omitting `NOT NULL`/`DEFAULT`.
- **Tall context menus ran off the bottom of the window** — the open-position clamp under-estimated menu height, clipping the last items. The menu now measures its real size after mount and shifts to stay fully on-screen.
- **`COPY … FROM stdin` after comment headers** — pg_dump prefixes each COPY with a `--` comment block, which made the script runner miss the COPY (it saw `--`), send it via `batch_execute`, and desync the protocol ("unexpected message from server"). COPY is now detected by the first non-comment token, and `copy_in` receives the comment-stripped statement.
- **Dollar-quoted function bodies corrupted by autocomplete** — Enter no longer silently accepts a completion (accept is **Tab-only**), and `$`-sigils (`$_$`, `$1`) no longer trigger completion. Fixes `CREATE FUNCTION … AS $_$ … $1 … $_$` failing with "syntax error at or near 1".
- **Empty export writes no file** — the output file is created lazily on the first row, so a 0-row result never touches disk.
- **Cropped UI on launch** — default window is now 1200×820 (min 900×600, centered); the connect screen scrolls if its form is taller than the window.
- **Error surfacing** — `tokio-postgres` errors previously surfaced as the useless string "db error"; now the real Postgres message (DbError) or source-chain detail is shown. Added a precise message when a saved keychain password can't be read in unsigned dev builds.

### Known issues / dev notes
- macOS keychain ties items to the binary's code signature; each `cargo` rebuild re-prompts and can invalidate dev-saved passwords. Production (signed) builds are seamless. Optional encrypted-on-disk dev fallback available on request.
- TLS not yet implemented (local / LAN only) — required before connecting the work server (default to read-only + guard destructive queries then).
