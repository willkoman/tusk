# Changelog

All notable changes to **Tusk** (fast native Postgres-first DB client). Format loosely follows Keep a Changelog. Newest first.

## [Unreleased]

### Added
- **Editor + sidebar follow the connected driver's dialect.** The SQL editor's dialect (highlighting, keyword/function/type autocomplete) now tracks the connected database instead of a manual selector — `activeDialect = driverDialect(capabilities.kind)` (DuckDB → the PostgreSQL dialect, since its SQL is PG-compatible). The redundant toolbar dialect picker was removed. **Identifier quoting is dialect-aware** (`sql/ident.ts` `ident`): MySQL emits backticks (`` `users` ``), the rest standard double-quotes — set once per connection via `setSqlDialect`, so it flows automatically into generated query scaffolds (Select/Insert/Update), grid sort/filter wrapping, and the sidebar DDL builders. Deferred: the statement lexer's backtick spans and deeper per-dialect DDL *syntax* (types, `AUTO_INCREMENT` vs `SERIAL`) — quoting is correct now, full DDL-syntax variants are a follow-up.
- **MySQL driver (network).** A fourth `Backend::MySql` arm via `mysql_async` — its `Pool` is `Send + Sync` (no `!Sync`-connection problem) and its `Value` enum makes all-text extraction easy. Connect over TCP (host/port/user/password/database; sslmode maps to `SslOpts`, with cert/host verification only for `verify-ca`/`verify-full`), stream queries (LIMIT/OFFSET pager), and introspect via `information_schema` (databases-as-schemas → sidebar tree + autocomplete + table detail incl. PK from `column_key`). DDL is non-transactional (capability `transactional_ddl: false`); cancel is a no-op for now. Enabled in the connect-screen picker (🐬; port defaults to 3306). **Compile-verified only — needs a live MySQL to exercise** (no embedded server to unit-test against). Export/import/server-lint stay PG-only.
- **SQLite driver (embedded, bundled).** A third `Backend::Sqlite` arm (`rusqlite`, `bundled` — tiny static SQLite): connect to a `.sqlite`/`.db` file or `:memory:` (read-only via `SQLITE_OPEN_READ_ONLY`), stream queries (LIMIT/OFFSET pager; `ValueRef` already yields text per cell, so no cast needed), and introspect via `sqlite_master` + `PRAGMA table_info` (single `main` schema; feeds the sidebar tree + autocomplete + table detail). Cancel is a no-op (queries are local/fast). Enabled in the connect-screen driver picker (🪶). Exercised by a unit test (open → page → NULL → introspection). Export/import/server-lint remain PG-only.
- **Driver picker on the connect screen + per-driver mascots.** The new-connection form has a **Driver** selector (PostgreSQL · DuckDB live; SQLite · MySQL staged "(soon)"). Choosing DuckDB swaps the host/port/user/SSL fields for a **Database file** path + **Browse…** (native picker; blank = in-memory) and hides the PG-only Save/Save-password/Connect-on-startup. The brand icon **adapts to the database** — 🐘 Postgres · 🦆 DuckDB · 🪶 SQLite · 🐬 MySQL — on the connect card, the topbar (reflecting the connected driver), the driver options, **and the OS window title** (`🦆 Tusk — DuckDB` while connected, `Tusk` otherwise; needs the `core:window:allow-set-title` capability); the topbar label/version follow the driver too. On connect the app fetches `capabilities` and **gates features** on them: the search-path selector, **Import**, and **Export** hide on drivers that don't support them (so DuckDB doesn't surface PG-only actions). DuckDB connects ad-hoc (profiles stay Postgres for now).
- **DuckDB driver (embedded, bundled).** A second `Backend::Duck` arm: connect to a DuckDB file or `:memory:` (read-only honored at the file level), run/stream queries, and introspect (sidebar tree + autocomplete + per-table columns) via `information_schema`. The `duckdb` crate is bundled (`features = ["bundled"]`) — libduckdb is statically compiled, so the installer is self-contained (larger binary, slower first build). Query values render as text via DuckDB's native `CAST(COLUMNS(*) AS VARCHAR)` (matches the all-text model, handles dates/decimals); paging is LIMIT/OFFSET over the base query (no server cursor). The `Connection` (Send, `!Sync`) is wrapped in a `Mutex` so command futures stay `Send`. Cancel maps to DuckDB's `InterruptHandle`. Not yet wired to the connect screen (next: driver picker) — but exercised by a unit test (open → COLUMNS(*) cast → paging → NULL → introspection). PG-only paths (DDL reconstruction / export-stream / server-lint / import) still error on DuckDB until abstracted.

### Changed
- **Driver abstraction (groundwork for multi-DB: DuckDB / MySQL / MSSQL).** New `src-tauri/src/driver.rs` introduces a `Backend` enum (today only `Pg`) that owns the connection-level surface the app needs — `query` / `run_single` (streaming cursor) / `run_script` / `fetch_page` / `execute` / `apply_search_path` / `rollback_cursor` / `reopen` / `cancel_handle` / `capabilities`. `ConnState` moved here (`{ backend, read_only }`); cursor state now lives in the backend. All of `lib.rs` is now driver-agnostic for execution; PG-specific introspection / DDL / export-stream / server-lint / import still reach the raw client via `Backend::pg()` until each is abstracted per driver. A `Capabilities` struct (server_cursor / bulk_copy / schemas / search_path / transactional_ddl / tls / keychain / permissions) is exposed via a new `capabilities` command so the UI can gate features per driver. Pure refactor — no behavior change.

### Added
- **Cancellable export & import; controls locked while running.** Both dialogs now disable every control except the cancel button while the operation runs (a `<fieldset disabled>` greys the whole form; the ✕ and overlay-dismiss are blocked). Cancel is *immediate*: a new `cancel_operation` command sends a Postgres `CancelRequest` over a fresh connection (via the client's `CancelToken`), interrupting the in-flight query. **Export** is a read — its cancel button is **Cancel export**; on cancel it just stops and deletes the partial file (the internal read transaction is closed, but nothing was mutated, so the UI doesn't mention rollback — it reports "Export cancelled."). **Import** writes, so it runs `CREATE` + `COPY` in one transaction and its **Cancel & roll back** button rolls the whole thing back (nothing half-created; "Import cancelled — rolled back."). `CancelToken`s are armed per connection just before the operation and disarmed after, kept outside the per-connection lock so the cancel can reach them.
- **Loading spinners across every async affordance.** Beyond the centered result-pane overlay, a small inline spinner now shows on: the **Run** button (while a query runs), the **statement run-gutter** — the `▶` on the *running* statement (the one under the cursor; clicking another `▶` moves the cursor there) becomes a spinner, the **Load all** button, and the **streaming…** status — which now spins *only during an actual in-flight `fetch_more`* (a new reactive `fetchingMore`); when more rows merely remain but nothing is being fetched it reads a static "idle" instead of spinning forever, the **Connect** button, and the sidebar **Refresh** button (while the object tree reloads). Shared `.spinner-sm` (inherits `currentColor`, works on any button) + `.cm-run-spinner`; solid colors only for WKWebView.
- **Loading spinner over the output while a query runs.** A centered, animated ring overlays the result pane whenever `running()` is true (faint backdrop dims the prior/stale grid). Pointer-events pass through; solid colors only (no `color-mix`) for WKWebView reliability.
- **Result-grid overhaul** (extracted from `App.tsx` into `src/ResultGrid.tsx`). A premium, read-only, highly-flexible grid:
  - **Two-axis virtualization** — windows rows *and* columns (variable per-column widths via prefix-sum offsets + binary search), so wide (50+ col) × deep (1M+ row) results stay smooth; a frozen header + row-number gutter implemented as synchronized transform panes (not `position:sticky`, for reliable WKWebView rendering).
  - **Click / drag / right-click** — click selects a cell; shift-click / drag selects a rectangular range (with edge auto-scroll); the row-number gutter selects rows; a header click selects the column; the corner selects all. **Keyboard nav**: arrows + Shift-extend, Home/End, ⌘/Ctrl+Home/End, PageUp/Down, ⌘/Ctrl+A, ⌘/Ctrl+C. **Copy**: ⌘/Ctrl+C copies the selection as TSV (spreadsheet-pasteable); right-click → Copy as CSV / JSON / Markdown, copy cell/column, View value.
  - **Columns**: drag a border to **resize**, double-click to **autofit** (canvas-measured), drag a header to **reorder**, right-click to **hide/show** — all display-only (never change the query).
  - **Server-side sort** — clicking a header cycles asc→desc→none (Shift-click = multi-sort with order numbers); re-runs by wrapping the base query `SELECT * FROM (<q>) _tusk ORDER BY <ordinal> …` (ordinal position dodges duplicate-`SELECT *`-name ambiguity) and re-streaming. **Server-side filter** — a toggleable per-column filter row (`<col>::text ILIKE '%…%'`, debounced, AND-combined) re-runs with a WHERE. Both gated to wrappable base queries (select/with/table/values).
  - **Streaming polish** — earlier prefetch (viewport-relative lead), a **Load all / Cancel** affordance that drains the cursor while staying responsive, and row-count status. New: `src/grid/query.ts` (wrap helpers); `tabs.ts` gains `GridView` (widths/order/hidden/sorts/filters) + `ResultSnapshot.baseQuery`/`epoch`.
- **Per-console active schema (search_path).** A toolbar selector sets each tab's working schema; the console then applies `SET search_path TO "<schema>", public` (or `RESET` for "(default schema)") before every run, validate, and scope=all export — so `SELECT * FROM actor` resolves to that schema instead of forcing `"public"."actor"`. The setting is per-tab (persisted), applied per run over the shared connection so tabs stay isolated. Autocomplete offers that schema's tables **unqualified** (and ranks them above others); **generated queries** (Select all rows, Generate SELECT/INSERT/UPDATE) drop the schema prefix when the object is in the active schema (`qualifyIn`); export scope=all uses the producing tab's schema (captured in the frozen `exportSrc` snapshot). `run_query`/`validate_sql`/`export_to_file` gained an optional `searchPath` param (schema quoted via `db::ident`).

### Fixed
- **Streaming that broke mid-result failed silently.** When the connection dropped while paging a large result (idle timeout, server restart, network blip — the kind that logs `[tusk] postgres connection error: error communicating with the server` to the terminal), the rows simply stopped with no indication in the app. Two silent paths fixed: (1) `fetch_more`'s `ensure_alive` would re-open the dead connection — which discards the server-side cursor (it lived in a transaction on the old connection) — and then report `done: true`, presenting a truncated result as complete; it now detects the lost-cursor case (`was_streaming && !cursor_open`) and returns an error instead. (2) `loadMore`'s catch logged to the console and marked the result done; it now surfaces the message in the result error banner (over the rows fetched so far) and sets the status to `streaming stopped — …`, then stops paging. Re-run the query to load the rest.
- **Result grid jumped to the top on every mutation (and felt like sort/resize/reorder were "broken").** The grid's scroll/selection-reset effect keyed on `${tabId}:${epoch}`, but `on()` re-runs its callback whenever a tracked dependency *notifies* — not only when the value changes — and `epoch` is read through App's `activeTab()` memo, whose identity changes on every `patchTab`/`patchResult`. So appending a streamed page, resizing/reordering/hiding a column, or any other grid edit re-fired the effect, took the `switched === false` ("new query") branch, and slammed `scrollTop` back to 0 while clearing the selection — on each `mousemove` of a resize drag, no less. The key is now a `createMemo`, so it dedupes by string value and the reset fires only on a real tab switch or new-query epoch bump. Verified in the harness: append/resize/reorder while scrolled to row ~180 keep the scroll position (was → 0); a sort click still resets to top on purpose (it re-streams the wrapped query).
- **Result grid froze/crashed when scrolling a large table.** Every scroll frame persisted the scroll position into the per-tab `gridView` via `setView`, which rebuilt the tabs array and invalidated `activeTab` — cascading a full reactive recompute across the whole App (editor + every memo) on each frame, and forcing the grid's own column-geometry memos (`displayCols`/`offsets`) to recompute too. Scroll position now lives in a non-reactive per-tab `Map`; the local `scrollTop`/`scrollLeft` signals (which only the row/column window memos depend on) drive virtualization, and nothing writes to shared state on scroll. Verified on a 50-col × 200k-row grid: zero `setView` calls during a scroll burst, cell count stays windowed (~128–192), correct rendering at row 99,000 / far-right, frames ≤ ~10 ms.
- **Editor error squiggles were invisible.** The lint CSS used `border-bottom: 1.5px wavy` (`wavy` is not a valid border style) and a later attempt used `text-decoration-style: wavy`, which WKWebView (the macOS runtime) renders unreliably — both while `background: none` had removed CodeMirror's default squiggle. Now drawn with a repeating inline-SVG wavy underline (the same cross-engine mechanism CodeMirror uses), recolored to the theme — red errors, blue warnings, grey info. Diagnostics themselves (heuristic + schema-aware + server) were generating correctly the whole time; only the underline was unpainted.
- **Trailing-comma lint false-positive on string/literal lists.** The check scanned the comment/string-masked statement, where string values are blanked to spaces, so `IN ('a','b','c')` looked like `(   ,    ,    )` and the last comma was flagged as trailing. Now span-aware: a string/quoted/dollar span after the comma counts as a real element. Numbers/identifiers were never affected.
- **Active-statement highlight bled into the previous block.** A statement's span starts right after the previous `;` (still on that statement's closing line) and may include leading blank lines, so the highlight covered the prior block's last line. Now trims leading/trailing whitespace before computing the line range. The per-statement run-gutter `▶` is also larger (font 10→13px, wider gutter, hover scale).
- **Generating SQL / opening a table no longer clobbers the current tab.** Generate SELECT/INSERT/UPDATE and double-click / "Select all rows" now open a **new tab** whose active schema is the relation's — so the generated query stays unqualified (`qualifyIn`) and resolves via `search_path`. Generated/peek tabs aren't marked dirty (regenerable; editing still marks them dirty). Edit-as-SQL / Copy-DDL-to-editor keep inserting at the cursor.
- **Export rejects multi-statement input.** `export_to_file`'s query path now `script::split`s and requires a single statement, so an internal `;` (e.g. a trailing `DROP`) can't ride into the `DECLARE … CURSOR FOR`. xlsx sheet names are capped at Excel's 31-char limit; `loadMore` reads the captured tab's rows post-await (no cross-tab merge on a mid-fetch tab switch).
- **Tabbed editor + real save/open flow.** The editor is now multi-tab: each tab keeps its own SQL buffer, file binding, undo/cursor/fold state (per-tab CodeMirror `EditorState`), and its own **result-grid snapshot** (switching tabs swaps the grid). Because there's one server-side cursor per connection, only the tab you run from streams live — running elsewhere freezes the prior tab's grid at the rows it fetched (`cursorOwnerTabId` gates `fetch_more` so scrolling never pages the wrong tab's cursor). New tab strip with dirty dots + close (×); **New** (⌘/Ctrl+T), **Close** (⌘/Ctrl+W, confirm if unsaved), **Open** (⌘/Ctrl+O), **Save** (⌘/Ctrl+S), **Save As** (⌘/Ctrl+Shift+S). Open/Save use native dialogs + on-disk paths via new backend `read_text_file`/`write_text_file` commands (replacing the old blob-download "Save" and hidden-input "Open"); the title tracks the file basename and a dot marks unsaved edits. The per-connection tab set (buffers/paths, not results) persists to localStorage (`tusk.tabs.${connKey}`) and restores on reconnect (replaces the single-buffer store). New: `src/tabs.ts`.
- **DataGrip-style export configurator + Excel.** The statusbar `Export…` opens a full configurator (`src/forms/ExportDialog.tsx`): **format** (CSV/TSV/JSON/SQL/Markdown/**Excel xlsx**); **delimited options** (delimiter incl. custom char, quoting always/as-needed/never, quote char, header on/off, NULL representation empty/"NULL"/custom, LF/CRLF line endings, UTF-8 / UTF-8-with-BOM); **column selection** (include/omit + reorder); **scope** (all rows = re-run & stream, or just the rows loaded in the grid) and **destination** (file or clipboard for text formats); **SQL** specifics (target table, multi-row INSERT, include CREATE TABLE); **Excel** specifics (sheet name, bold header, auto-filter, freeze header). Live preview of the first rows. **Excel** uses `rust_xlsxwriter` (pure Rust, no C deps) and **rolls into Sheet2/Sheet3/… every 1,048,576 rows** so all data exports; note xlsx buffers the whole workbook in memory (text formats still stream in constant memory). `export.rs` is now fully options-driven (`ExportOptions` serde-mirrored from `src/export.ts`); `export_to_file` takes either a query (stream) or inline rows (loaded). The clipboard path formats in TS (`formats.ts` `formatWithOptions`), kept byte-for-byte in parity with the Rust formatters.
- **Premium SQL editor overhaul.** The editor (`src/SqlEditor.tsx`) is rebuilt as a composition of focused extension modules under **`src/editor/`** — performance, stability, and multi-dialect extensibility kept paramount.
  - **Auto-fold large inline literals** *(headline)* — a giant `IN (1,2,…,5000)`, `ARRAY[…]`, big tuple, or long string / `$$ … $$` body collapses to a compact pill (`…5,000 items…` / `…1.2 KB…`) so the query stays scannable; the cursor entering a folded region expands it, leaving re-folds it. **Display-only** (the document is never modified → `Run`/export always see the full query). Detection runs on a shared SQL lexer (`src/editor/lexer.ts`, a faithful TS port of `script.rs`) so brackets/commas inside strings, comments, and dollar-quoted bodies are never miscounted. Thresholds: 100 items / 200 chars.
  - **Layered diagnostics** replacing the noisy Lezer "Syntax error" linter: fast **client heuristics** as-you-type (unmatched/unclosed parens, trailing commas, `DELETE`/`UPDATE` without `WHERE`) + **schema-aware identifier checks** (unknown table after FROM/JOIN, unknown `alias.column`, alias-resolved, with closest-match quick-fix) + **server-side validation** — a new Rust `validate_sql` command PREPAREs each statement (parse + plan, **never executes**, read-only safe, isolated from the streaming cursor) for parser-grade Postgres errors mapped to the exact offset. Server lint is debounced and skipped while a query runs.
  - **QoL:** SQL **formatting** (`sql-formatter`, dollar-quoted bodies preserved byte-for-byte) via a toolbar button / `Shift-Alt-f`; manual **code folding** with a fold gutter; **find & replace** panel (`@codemirror/search`, regex/replace-all, ⌘/Ctrl+F); **multiple selections** + Alt-drag rectangular selection + occurrence highlighting; a **per-statement run gutter** (`▶`) + active-statement highlight + `Ln/Col · Stmt i/N` status-bar readout + run-current-statement (`Mod-Shift-Enter`).
  - **Persisted editor state** (`src/store.ts`, localStorage) — per-connection scratch buffer restored on reconnect, plus prefs (font size, word wrap, **dialect selector**, auto-fold/server-lint toggles); live dialect/theme switching via CodeMirror compartments (no rebuild, no history reset). The external-value sync is now guarded so restores don't pollute undo history.
- **Sidebar visual overhaul.** Hand-built monochrome SVG icon set (`src/Icons.tsx`, Lucide-derived, no dependency) replaces the emoji — neutral for structural objects, semantic accents for keys (🔑 amber) / foreign keys (blue) / unique (teal) / check (green). Plus: rounded **pill** hover/selection rows, **count-badge pills** for object/column counts, **uppercase section headers** (TABLES / VIEWS / COLUMNS / …), **indent guides** connecting the hierarchy, a proper **search field** (leading magnifier icon), SVG header buttons (new / import / refresh), a thin custom scrollbar, and name-over-type truncation. Dead pre-`Tree` CSS removed.
- **Modify Table — DataGrip-style editor.** A `Modify table…` action opens a rich dialog: an editable column grid (rename / type / nullable / PK / default / comment, add & drop columns), checklists to drop existing indexes/constraints, and table rename + comment — all diffed into the minimal `ALTER` script shown as a **live SQL preview** (with the usual Edit-as-SQL / Apply). Type, default, `CHECK`, `USING`, and partial-index `WHERE` fields are now **`SqlField`s**: single-line CodeMirror inputs with Postgres syntax highlighting and autocomplete (types, functions, and the table's columns). The create/add-column/constraint/index dialogs use the same SQL-aware fields.
- **Context-aware “+” menu + sidebar selection.** Clicking a tree node selects it (highlighted); the sidebar’s **＋** button opens a menu whose options follow the selection — New column/index/constraint on the selected table (or the table owning a selected column/index/constraint), New table in the selected schema, plus New schema / New database. Creating a **database** is now *only* offered here; **Create schema** moved onto the database node; the sidebar-background menu is Refresh / Clear filter / New….
- **App-wide custom context menus.** Every interactive surface has its own right-click menu (the native WebView menu is suppressed): **result-grid cells** (copy value / row / column as TSV or JSON, view full value in a modal, copy column name), **column headers** (copy name / column / all rows as TSV/JSON), the **SQL editor** (cut / copy / paste / select-all / toggle comment / run selection-or-all — via new `EditorApi` methods + a clipboard helper), and **saved-connection rows** on the connect screen (connect / edit / duplicate / set-or-unset default / copy connection string / delete), plus a **sidebar background** menu (refresh / clear filter / create schema·database). The context menu + value viewer now render above both the connect and workspace screens.
- **Sidebar workbench — object actions.** The DB explorer is now a full workbench: right-click any node for a context menu of actions. Visual form dialogs (with a **live SQL preview** + an **Edit as SQL** escape hatch that scaffolds the generated statement into the editor) for **Create Table** (column builder: name/type/null/PK/default), **Add/Edit Column**, **Add Index** (columns, method, unique, partial WHERE), **Add Constraint** (PK / unique / FK with referenced table+columns + ON DELETE/UPDATE / check), **Create Schema**, **Create Database**, **Rename**, **Duplicate** (LIKE … INCLUDING ALL, optional data), and **Edit comment**. Destructive ops (**Drop**, **Truncate**, drop column/index/constraint/schema/database) go through a confirm dialog showing the exact SQL + a **CASCADE** toggle (and RESTART IDENTITY for truncate). Plus **Copy DDL** (to clipboard or editor), **Copy name / qualified name**, **Generate SELECT/INSERT/UPDATE**, matview **REFRESH [CONCURRENTLY]**, and sequence **RESTART/RENAME**. Mutating items are disabled on read-only connections; all mutations run through the existing `run_query` path and refresh the tree. New frontend: `ContextMenu.tsx`, `Dialog.tsx`, `WorkbenchDialogs.tsx`, `forms/*`, pure SQL builders in `sql/ddl.ts` + quoting in `sql/ident.ts` (mirrors Rust `db::ident`).
- **DDL reconstruction (Copy DDL)** — backend `object_ddl` (`src-tauri/src/ddl.rs`) rebuilds runnable `CREATE` statements from `pg_catalog` (pg_dump-style, no shelling out): tables (columns with identity/generated/serial defaults, PK/unique/check inline, **FKs as trailing ALTERs**, plain indexes only — constraint-backed ones skipped, table+column comments), views/matviews (`pg_get_viewdef`), functions (`pg_get_functiondef`, overloads emitted, aggregates/window funcs flagged), and sequences (`pg_sequences`). User input is bound as query parameters then driven by OID. Out of scope (noted, not silently wrong): partitioning, inheritance, RLS, triggers, storage params, tablespaces, collations.
- **Lazy-loaded object tree** — `db_tree` now returns a **shallow** tree (databases → schemas → object names/kinds) for fast connect on large DBs; a table's columns/indexes/constraints (+ comments) load on expand via the new `table_detail` command and are cached. Autocomplete is decoupled from the tree and fed by `list_schema` (previously dead code). Empty schemas now appear (so you can create objects in them).
- **Object & column comments** — shown on hover in the tree (table rows + column tooltips) and editable via the **Edit comment** action (`COMMENT ON … IS …`, empty removes via `IS NULL`).
- **Sidebar object filter** — a search box filters the tree by name (auto-expanding matching schemas/categories).
- **Project scaffold** — Tauri v2 + SolidJS + TypeScript, Rust backend. Working name **Tusk** (Postgres elephant nod).
- **Postgres backend** (`src-tauri/src/db.rs`, `lib.rs`) — connect via `tokio-postgres`; arbitrary user SQL over the text protocol (`simple_query`) so any column type renders without per-type mapping.
- **Streaming reads** — large `SELECT`s run through a server-side cursor (`BEGIN` / `DECLARE` / `FETCH FORWARD` in 1000-row pages) with `fetch_more`; non-cursorable statements run directly and report rows-affected. This is the "millions of rows without choking" wedge.
- **Schema introspection** — `list_schema` returns schemas → tables → columns (name + data_type).
- **Virtualized result grid** (`src/App.tsx`) — renders only visible rows; millions scroll smoothly. Sticky header, NULL styling, streaming status bar, elapsed-ms.
- **CodeMirror 6 SQL editor** (`src/SqlEditor.tsx`) — syntax highlighting, line numbers, bracket matching, undo history, ⌘/Ctrl+Enter to run.
- **Saved connections** (`src-tauri/src/profiles.rs`) — profiles persisted to `connections.json` (app config dir); passwords stored in the **OS keychain** (`keyring`, macOS `apple-native`) — never plaintext, never sent to the frontend. `connect_profile` loads the password server-side. Edit / delete; ad-hoc connect still supported. **Connect on startup** — a per-profile toggle auto-connects to one chosen profile on launch (at most one; setting it clears the flag on others).
- **Context-aware, multi-dialect autocomplete engine** (`src/sql/dialects.ts`, `src/sql/completion.ts`) — custom completion source: clause-aware (tables after FROM/JOIN, columns after SELECT/WHERE/ON/GROUP BY/…), table-alias resolution (`u.` → that table's columns), schema qualification (`schema.table.col`), ranked in-scope columns > tables > functions > keywords. Per-dialect keyword/function/type lists (Postgres complete; MySQL/SQLite/MSSQL stubs ready for when those drivers land). Uppercase keyword completions; column types shown inline. Accepts completion on **Tab**; **live auto-capitalization** of keywords (SELECT, FROM, GROUP BY, JOIN, …) as you type, skipping strings and qualified names.
- **Windows / cross-platform deploy prep** — target-specific `keyring` backends (macOS Keychain / Windows Credential Manager / Linux Secret Service); lightweight Windows bundle (NSIS **per-user**, WebView2 `downloadBootstrapper`); GitHub Actions `release` workflow (`.github/workflows/release.yml`) builds + publishes mac (universal) + Windows installers on a `v*` tag as a draft release.
- **README** — overview, features, quickstart, project layout, and roadmap.
- **Schema sidebar previews** — expandable tables show columns + types inline; **Refresh** button; **auto-refresh after DDL** (`CREATE`/`ALTER`/`DROP`/…). Single-click previews, double-click runs `SELECT *`.
- **Editor QoL** — open / save `.sql` files (webview-native, no plugins); **run selection vs whole** (selected text runs alone, otherwise the full editor); auto-close brackets & quotes.
- **Resizable editor / results split** — drag the divider between the SQL editor and the result grid; the grid re-virtualizes to the new size.
- **TLS connections** — `sslmode` per connection (`disable` / `prefer` / `require` / `verify-full`) over native platform TLS (SecureTransport / SChannel — no OpenSSL on mac/Windows). `prefer`/`require` encrypt without verifying the cert (libpq semantics, works with self-signed); `verify-full` verifies. Persisted on saved profiles.
- **Read-only connections** — opt-in per connection: sets `default_transaction_read_only = on` server-side **and** blocks writes/DDL client-side with a clear message. Persisted on saved profiles. Safe for browsing production.
- **Import / export (multi-format)** — **streaming export** of the current query to **CSV / TSV / JSON / SQL inserts / Markdown**: backend (`export_to_file` + `export.rs`) reads a server-side cursor in 10k-row batches, formats each batch, and writes straight to a file chosen via a **native save dialog** — constant memory, any table size. Import **CSV / JSON** into an existing table or a new auto-created table (all-`text` columns) via Postgres `COPY FROM STDIN` (`import_rows`). Import dialog: file pick, header toggle, target selector. Both blocked on read-only connections (import).
- **SQL script runner** — Run auto-detects multi-statement input (e.g. an opened `.sql` dump) and runs it as a script in one transaction (`src-tauri/src/script.rs`): a lexer splits statements respecting comments, quoted strings/identifiers and **dollar-quoted bodies**, executes `COPY … FROM stdin` + `\.` data blocks via the COPY protocol, and skips psql backslash meta-commands. Single statements still stream to the result grid. Reports statement/row counts, or the failing statement with context. Lets you run `pg_dump` files (e.g. pagila.sql).
- **Database explorer sidebar** — full object hierarchy (databases → schemas → Tables / Views / Sequences / Functions, and per-table **Columns / Indexes / Constraints**) with rich icons (🔑 primary key, 🔗 foreign key, 🔒 unique, ✓ check), column types + NOT NULL, and index/constraint definitions on hover. Backend `db_tree` introspects `pg_catalog` (`src-tauri/src/tree.rs`); UI in `src/Tree.tsx`. Sidebar is now **resizable** (drag the divider); double-click a table to `SELECT *`.
- **SQL error highlighting** — live syntax-error underlines + gutter markers from the Lezer parser (`@codemirror/lint`).
- **Editor larger than results by default** (~60/40 split from window height), still freely resizable.

### Fixed
- **Network failures fail fast; query duration is never capped.** A query on a dead connection used to spin on "Running…" indefinitely (TCP retransmit can take many minutes). Now a 10s **connect timeout** bounds the open/reconnect path and **aggressive TCP keepalives** (5s idle, 2s interval, 3 retries, 15s `tcp_user_timeout`) drop a genuinely dead connection in ~10-15s → the in-flight query errors and the next action auto-reconnects. A slow-but-alive query keeps getting keepalive ACKs and runs **as long as it needs** (no artificial timeout). The Run button shows a **live H:M:S counter** while a query runs.
- **Dropped connections now auto-recover.** When a Postgres connection was closed underneath the app (idle timeout, server restart, network blip), every subsequent action failed permanently with no way out but disconnect + reconnect. The backend now retains each connection's config (server-side only, never sent to the frontend) and **transparently re-opens** a closed connection on the next action (`ensure_alive`, gated on `Client::is_closed()`); `run_query` additionally reconnects + retries once if a query dies mid-flight. Verified end-to-end (terminate the backend server-side → `is_closed()` flips → next query reconnects and succeeds).
- **Native WebView right-click menu showed instead of the app menu** — the OS/WebView context menu is now suppressed app-wide (`document` `contextmenu` `preventDefault`), so right-click consistently opens the sidebar's own action menu (and nothing in the editor/grid).
- **Sidebar boolean flags were always false** — catalog queries cast booleans to `::text` (e.g. `(NOT a.attnotnull)::text`) and compared against `"t"`, but `bool::text` yields `"true"`/`"false"` (only a *bare* bool renders `"t"`/`"f"` over the text protocol). So every column showed as `NOT NULL`, and index `unique`/`primary` flags were wrong. Found via GUI test against a real DB. Fixed by dropping the `::text` casts (tree.rs `table_detail`, ddl.rs `object_ddl`). This also fixed Copy DDL emitting constraint-backed PK/unique indexes (the `backs` dedup flag was stuck false → duplicate-index errors on replay) and omitting `NOT NULL`/`DEFAULT`.
- **Tall context menus ran off the bottom of the window** — the open-position clamp under-estimated menu height, clipping the last items. The menu now measures its real size after mount and shifts to stay fully on-screen.
- **`COPY … FROM stdin` after comment headers** — pg_dump prefixes each COPY with a `--` comment block, which made the script runner miss the COPY (it saw `--`), send it via `batch_execute`, and desync the protocol ("unexpected message from server"). COPY is now detected by the first non-comment token, and `copy_in` receives the comment-stripped statement.
- **Dollar-quoted function bodies corrupted by autocomplete** — Enter no longer silently accepts a completion (accept is **Tab-only**), and `$`-sigils (`$_$`, `$1`) no longer trigger completion. Fixes `CREATE FUNCTION … AS $_$ … $1 … $_$` failing with "syntax error at or near 1".
- **Empty export writes no file** — the output file is created lazily on the first row, so a 0-row result never touches disk.
- **Cropped UI on launch** — default window is now 1200×820 (min 900×600, centered); the connect screen scrolls if its form is taller than the window.
- **Error surfacing** — `tokio-postgres` errors previously surfaced as the useless string "db error"; now the real Postgres message (DbError) or source-chain detail is shown. Added a precise message when a saved keychain password can't be read in unsigned dev builds.

### Known issues / dev notes
- macOS keychain ties items to the binary's code signature; each `cargo` rebuild re-prompts and can invalidate dev-saved passwords. Production (signed) builds are seamless. Optional encrypted-on-disk dev fallback available on request.
- TLS not yet implemented (local / LAN only) — required before connecting the work server (default to read-only + guard destructive queries then).
